# 먼저 모티프를 고르는 단계 (P1)

상태: 선택 기능. 기존 piece와 예시 악보를 바꾸지 않습니다. 생성 후보는 작곡 재료이며 자동 품질 승인이나 코퍼스 학습 결과가 아닙니다.
근거: 2026-10-24 사용자 의견 “모티프와 프레이즈를 만들어서 발전시키는 과정이 부족하다고 느낍니다.”

## 실행

design.json의 basics(박자·조성·장단조·빠르기·급수), impression, 선택적인 theme.constraints를 읽습니다. 이 단계는 완성곡 form 없이도 실행됩니다. impression은 비교 페이지에 설계를 보존하는 맥락이며, 자유 문장을 해석해 자동으로 기법을 고르는 언어 모델은 아직 없습니다.

```powershell
python -m musigen motifs <작업 폴더> --count 8 --seed 0
python -m musigen motifs <작업 폴더> --include first.json second.json
python -m musigen choose <작업 폴더> motif-selection.json
python -m musigen choose <작업 폴더> m3
```

현재 한 마디 모티프, 3/4·4/4, 단선율을 지원합니다. `theme.constraints`는 `bars: 1`, `range: "C4-A5"`, `start_on_beat: false`, `rhythm: "syncopated"` 형태입니다. rhythm은 lyrical/syncopated. 당김음은 약박 시작 음이 다음 4분음표 박을 가로질러 지속되는 조건이며 잠정 정의입니다. 조성·급수·음역을 몰래 바꾸지 않습니다. 장단조와 1–10급을 받고 기존 musicomp 급수의 조표·동시음·손 벌림·왼손 음역 조건을 사용합니다. 기존 급수표는 오른손 속도·모든 연주 난이도를 평가하지 못합니다.

## 후보와 응답

기존 연산 realise로 리듬을 보존한 딸림화음 응답을 붙여 총 두 마디 맛보기를 만듭니다. 모든 후보의 반주는 같은 으뜸→딸림 블록 화음, 같은 빠르기·음량·샘플 피아노입니다. 저급수에서는 기존 급수 한도만큼 블록의 음 수를 줄이며 첫 급수는 단음입니다. 페달은 없습니다.

리듬 세포와 윤곽은 이번에 작성한 잠정 재료입니다. 전체 박을 채우는 조합을 만든 뒤 설계의 시작 박·당김음 조건으로 먼저 거릅니다. seed로 탐색 순서가 재현됩니다. 320번 상한은 음악 이론 수치가 아닌 잠정 계산량 상한입니다. 생성 음을 다시 측정한 시작 위치 집합과 윤곽 유형이 각각 중복되지 않는 후보만 채택합니다. 윤곽은 실제 음높이 차의 부호열에서 같은 방향의 연속을 합친 유형이며, 혼합형은 정확한 방향열을 표시합니다. 이름만 다르게 붙인 후보를 다양성으로 세지 않습니다. 초깃값에서 4–8음의 조합을 쓰며 이는 한 마디 맛보기의 잠정 범위입니다.

한 번의 제한된 탐색에서 6개 미만이면 중단 진단을 저장하고 종료 코드 2로 반환합니다. 6개 이상이어도 요청 수보다 적으면 partial과 종료 코드 2를 보고합니다. 부족한 윤곽·리듬 수·탈락 이유를 표시하며, 자동으로 규칙이나 상한을 늘리지 않습니다. 중단 상태의 choose는 거절합니다.

`--include`에는 musicanote-motif v1 JSON을 넣습니다. 기본 출처는 import이며, 작곡자가 직접 쓴 파일은 최상위 `origin: "composer"`로 구별합니다. 입력 사건과 출처는 보존합니다. 긴 클립·다성·설계 밖 음역은 명시적으로 거절하며 자르거나 임의 조성을 추정하지 않습니다. 한 마디보다 짧으면 맛보기에만 뒤 쉼을 붙이고 선택 모티프에는 붙이지 않습니다. 중복 include는 진단에 남기고 생성 후보로 나머지를 채웁니다. 가져온 곡의 화성을 안다고 주장하지 않으며 맛보기 반주는 공통 화성 제안입니다.

## 비교·선택과 P5 기록

`stage1_motifs/index.html`을 엽니다. 후보별 재생·반복, 전체 연속 재생, 두 후보 번갈아 재생, 이걸로, 한 줄 이유와 선택 내보내기를 제공합니다. 출력 폴더 전체를 정적 서버에 두어도 됩니다. 로컬 Verovio가 있으면 복사해 네트워크 없이 열리며, 없으면 고정 버전 CDN을 사용합니다. 피아노 샘플과 출처를 함께 제공합니다.

브라우저 선택은 후보 묶음 지문을 키로 localStorage에 기억합니다. 선택 내보내기는 서버를 수정하지 않습니다. `choose`가 실제 사용자 선택을 받은 뒤에만 다음을 만듭니다.

- `selections.jsonl`: 시간(UTC), stage, work, shown, chosen, origin, reason, design_sha256, set_id, selection_id. 추가 기록만 하며 자동 학습에는 쓰지 않습니다.
- `selected_motif.json`: 선택 기록과 정확한 모티프. P2 입력은 이 파일로 이어집니다.

설계 변경·후보 내용 변경·다른 묶음의 내보내기는 거절합니다. 같은 id도 후보를 다시 만들면 내용이 다를 수 있으므로 지문을 확인합니다. CLI id 지정은 현재 묶음에서 사용자가 선택한 것으로 기록합니다. 후보 생성 자체는 선택 기록을 만들지 않습니다. 현재 P1은 출처를 표시하는 공개 비교입니다. P4 눈가림은 별도 구현 단계이며 P1을 눈가림이라고 주장하지 않습니다.

`stage1_motifs/candidates.json`은 현재 묶음, `runs/<set_id>`는 이전 후보·2마디 XML·설계·악보·검사 보관입니다. 생성기를 다시 돌려도 기존 선택 이력과 이전 묶음은 보존합니다. 브라우저 음원은 같은 피아노 샘플을 쓰되 완성곡 페이지의 믹스 코드를 바꾸지 않는 독립 미리듣기입니다.

## 시험 설계

`examples/stages/lyrical_34/design.json`, `examples/stages/bright_44/design.json`을 작업 폴더에 복사해 실행합니다. 원음 악보를 공개 저장소에 넣지 않습니다. 입력 모티프·생성 악보·선택 이력은 output 아래 로컬 작업 폴더에 보관하고, 검증된 통계나 코드만 별도 검수합니다.

두 마디는 V로 열린 미완결 맛보기입니다. 기존 완성곡 검사가 끝의 으뜸화음 부재를 경고할 수 있으며, 원자료 checks.json에 보존합니다. 이 공통 종결 경고를 후보 품질 순위로 사용하지 않습니다. pickup/swing 설계는 P1에서 명시적으로 거절합니다.
