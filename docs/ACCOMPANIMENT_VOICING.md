# 반주 구성음과 마디 연결 수정 — 선택 기능

직전 [두 박자 시험](ACCOMPANIMENT_TRANSFER_TRIAL.md)에서는 자료 후보가 없어 작성 패턴으로 돌아온 마디에서 3음이 빠지고, 다음 자료 마디와 병행음정이 생겼습니다. 이번 기능은 검색 뒤의 실제 음표를 확인하고 필요한 음높이만 바꿉니다. 음악적 타당성은 아직 청취 검수 전이며 기본값은 꺼짐입니다.

## 사용

기존 `development.json`의 `design.accompaniment_plan` 구간에 `repair_voicing: true`를 추가하고 `musigen.blueprint_solo`의 `--corpus-accompaniment` 옵션으로 새 폴더에 생성합니다. 기존 JSON에 아래 키만 더하면 됩니다.

```json
{
  "bars": [1, 4],
  "role": "주제와 질문",
  "decision": "작성한 음형의 리듬과 쉼을 유지하며 구성음과 연결을 확인한다",
  "required_degrees": [3, 7],
  "entry_bass_range": [38, 55],
  "repair_voicing": true
}
```

```powershell
python -m musigen.blueprint_solo --work <입력 폴더> --out <새 출력 폴더> --corpus-accompaniment
```

자료 검색 결과와 자료가 없어 유지한 작성 패턴이 모두 대상입니다. 직접 쓴 왼손·둘째 성부·마디를 가로지르는 지속음·의도한 왼손 쉼은 보호합니다. 검색 계수나 원 자료는 바꾸지 않습니다. 최종 음표와 원 자료 출처는 기존 스냅샷에 저장되고 수정한 음의 출처에는 `|voicing`가 붙습니다.

## 수정 계약과 한계

1. 한 번에 한 음을 현재 음높이의 ±12반음 안에서 바꿉니다. 새 음은 지속하는 모든 화성 구간의 공통 구성음이어야 하며, 기존 비화성음은 재작성하지 않습니다. 화성은 명시된 계획만 사용합니다.
2. 음가·발음 시각·쉼·동시음 수·성부·아티큘레이션·슬러·각 화성 구간의 첫 발음 최저음을 보존합니다. 오른손·화성·국소 조성·셈여림·페달도 유지합니다. 첫 최저음이 원래 근음이라는 뜻은 아닙니다.
3. 먼저 명시한 요구 구성음의 생략을 줄이고, 다음으로 기존 외성 병행 사건을 줄입니다. 각 단계에서 새 3음·7음 생략이나 새 병행 사건이 생기는 후보는 거부합니다. 기존 난이도·왼손 음역·손 벌림·오른손 교차 검사도 통과해야 합니다.
4. 가능한 후보 중 남은 생략 수, 병행 수, 해당 치환의 반음 변화량, 마디·발음 시각·음순으로 결정합니다. 학습하거나 시험곡에 맞춘 가중치는 없습니다. 한 음씩 고치는 국소 탐색이므로 여러 음을 함께 바꿔야 풀리는 문제는 남을 수 있습니다. 미해결 요구와 병행은 보고서에 남기며 해결했다고 표시하지 않습니다.
5. 병행 검사는 기존 `musical_checks`와 동일하게 연속 발음 시각의 최상·최하음과 화음 기호 변화를 봅니다. 지속음은 포함하지만 발음 없는 음 종료 시각은 따로 샘플링하지 않습니다. 내성 성부 추적, 모든 평행·직행음정, 종합 대위법 검사가 아닙니다.

`accompaniment_report.json`의 `voicing_repair`에는 적용 가능/보호 마디, 바꾼 실제 음, 자료 유래/작성 패턴별 변경, 후보 검사 횟수, 남은 요구와 병행, 구현 코드 지문이 있습니다. 기존 `bars[].status/reason`은 **검색 단계**의 선택·유지 사유이며 후속 음 수정과 구별합니다.

## 고정 입력 비교

[A/B 피아노 듣기와 악보](http://127.0.0.1:8805/index.html). A는 직전 시험의 **B**를 그대로 가져온 기준판이고, B는 `repair_voicing`만 켠 판입니다. 새 모티프나 화성 진행을 작성한 시험이 아닙니다.

| 항목 | 고요한 창가 · 3/4 | 골목의 작은 걸음 · 4/4 |
|---|---|---|
| 실제 변경 | 14·15마디, 각각 한 음 | 6·14마디, 각각 한 음 |
| 왼손 3음·7음 생략 구간 | 2/16 → 0/16 | 1/19 → 0/19 |
| 솔로 병행 경고 | 1 → 0 | 2 → 0 |
| 자료 반주 적용 | 10마디 유지 | 9마디 유지 |
| 수정한 자료 유래 마디 | 0 | 0 |
| 수정한 작성 패턴 마디 | 2 | 2 |
| 검사한 단일 음 치환 후보 | 118 | 101 |

분모 16·19는 각 곡의 화성 구간이며 코퍼스 일반 성공률이 아닙니다. 후보 수는 탐색 중 검사한 치환 횟수로, 서로 다른 마디 자료 개수가 아닙니다. 구성음 생략은 해당 화성 구간의 **왼손에 한 번도 등장하지 않은 3음·7음**을 뜻하며 오른손까지 포함한 화음 결핍 판정은 아닙니다.

3/4는 14마디 마지막 G3를 B♭3으로, 15마디 3박의 E3를 C♯3으로 바꿨습니다. 4/4는 6마디 4박 화음의 G3를 E3으로, 14마디 마지막 A♭3을 C4로 바꿨습니다. 3/4의 14→15마디 병행8도, 4/4의 6→7·14→15마디 병행5도가 사라졌습니다. 자료 검색 결과는 동일하므로 이번 차이는 작성 패턴의 음 배치 수정에서 나왔습니다.

모든 악보 자동 검사 오류 0개. **3/4 공통 멜로디+화성 악보의 15→16마디 병행8도 경고 1개는 그대로**입니다. 공통 악보는 이번 수정 대상이 아니며, 두 솔로의 경고 0개를 전체 출력의 경고 0개로 표시하지 않습니다. 4/4 공통 악보의 경고는 0개입니다. 페달은 A/B 모두 없습니다.

모티프·공통 MusicXML 바이트, 상세 화성 사건, 실제 선율·화성·조성·표현, 전체 발음/음가/쉼, 각 화성 구간 첫 최저음, 보호 마디, 자료 선택·라이브러리·검색기·밀도 모델·급수를 대조했습니다. 비교 명령은 입력에서 수정 옵션 외의 변경을 거부합니다.

```powershell
# trial_input.json의 mode를 "voicing"으로 지정하고 baseline/planned 폴더를 준비
python -m musigen.accompaniment_trial --root output/voicing-v002
python -m http.server 8805 --bind 127.0.0.1 --directory output/voicing-v002
```

출력: `K:/MusicGeneration/accompaniment-voicing/output/voicing-v002`. 각 판에 피아노 재생·로마자 전환·XML/PDF 받기를 제공합니다. 219개 테스트 통과, 기존 기본 출력 바이트 동일, 4개 PDF 시각 검수, 파일 링크 58개 정상 응답을 확인했습니다. 사용자 청취 판단과 모바일 검수는 없습니다. 기술 검증 완료와 기본 적용은 구별하며 자동 스타일 생성과 P3/P4의 기존 중단 상태도 유지합니다.

다음 범위는 첫 베이스·리듬을 고정하면 해결할 수 없는 사례를 모아 내성의 연결과 성부별 해소를 따로 비교하는 것입니다. 이번 결과를 자동으로 좋은 학습 예제에 편입하지 않습니다.
