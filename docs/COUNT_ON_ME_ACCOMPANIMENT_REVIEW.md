# 같은 선율, 더 유연한 반주

2026-11-11, `codex/count-on-me-phrasing`. [비교 요약·두 악보](http://127.0.0.1:8808/count-on-me-phrasing.html), [A/B 악보와 재생](http://127.0.0.1:8808/count-on-me-compare.html#piece=count_on_me&version=v002).

사용자는 이전 곡에 “한결 낫네요. 개선 방안 아직 남은 게 있나요.”라고 평가했고, **현재 주선율과 화성을 유지하면서 반주 리듬·내성·음량 균형을 다듬는 비교판** 제안에 “좋습니다. 진행하세요.”라고 답했다. 이번 작업은 그 비교판이다. 이전의 상대적 개선 평가를 이번 결과에 대한 승인으로 옮기지 않는다.

## 보존과 변경

주선율 121개 음의 음높이·철자·음가·시각·성부·아티큘레이션, 39개 화성 구간, 조성·박자·빠르기, 기보 셈여림·헤어핀·페달을 그대로 유지했다. 공통 멜로디 + 상세 화성 XML/PDF는 이전과 바이트도 같다. 왼손 변경은 1–8, 13–16, 21–31마디이며, 재생용 음량은 별도의 선택 계획으로 적용한다.

| 구간 | 반주 수정 |
|---|---|
| 1–4 | 지속 베이스와 별도 내성의 진입을 나눠 첫 선율에 여백을 줌 |
| 5–8 | A–Ab의 반음 변화, G7의 F에서 C6의 E로 연결. 8마디 후반 양손 쉼 유지 |
| 9–12 | 이전 lyrical 반주를 구성음 보완까지 그대로 유지 |
| 13–16 | 펼침화음과 짧은 종결로 이동 밀도를 높임 |
| 17–20 | 기존 lyrical 절정 반주 유지 |
| 21–31 | 공통음과 순차·반음 진행으로 내성을 연결. 31마디 저음을 먼저 짚고 내성을 반 박 늦게 이음 |
| 32 | 기존 C6 종결과 마지막 한 곳의 페달 유지 |

새로운 자료 선택은 하지 않았다. 이전의 실제 musicomp lyrical 결과에 기반한 반주를 8마디에서 유지했고, 다른 구간은 작성자가 재구성했다. 32마디는 이전의 작성 종결을 보존했다. 자료 검색이나 자동 학습을 새로 실행한 것으로 표시하지 않는다.

첫 마디 Cmaj7은 5음 G를 생략해 가볍게 시작한다. 실제로 소리 나는 38개 화성 구간의 3음·7음은 빠지지 않았다. 24마디 후반 G7은 기존처럼 양손 쉼이므로 솔로에서 소리 내지 않는다. 요약 악보에는 전체 구성음을 남긴다.

## 내성과 리듬의 확인

기존 `musigen.inner_voices`로 실제 철자·옥타브·발음 시각·기보 성부를 지정했다. A–Ab, F–E, E–D, A–Ab–G, 재현의 A–G–A, 마지막 F–E–F–E 등 **17개 연결이 작성 의도와 일치**했다. 왼손 음높이 사건 209개 중 23개를 지정했으며 전체 내성 검증은 아니다. 31마디의 한 연결은 의도한 반 박 쉼을 포함하고, 나머지 16개는 연속한다.

A→Ab는 같은 음이름의 반음 변화이므로 온음계 `step_down` 검사를 사용하지 않았다. 기존 `within`의 1반음 한도로 대조하고 실제 하행량 -1을 기록했다. 곡을 위해 검사 규칙을 바꾸지 않았다.

왼손 발음 시각의 마디별 패턴은 9종에서 15종으로 달라졌다. 이전의 `0, 1.5, 2, 3박` 패턴은 20/32마디에서 4/32마디가 되었고, 수정판에서 가장 흔한 패턴은 `0, 2박`의 10/32마디다. 총 발음 시각은 117에서 96으로 줄었다. 마디별 새 발음 시각의 관찰이며 유지음·성부 수·음량이나 음악적 다양성을 모두 설명하는 점수는 아니다.

## 선택 기능: 재생 음량 계획

곡별 조건문 없이 `score.playback_balance`에 작성한 구간을 지정한다. 예:

```json
{
  "playback_balance": [
    {"bars": "1-8", "rh": 1.0, "lh": 0.85, "reduce_lh_chords": true},
    {"bars": "17-20", "rh": 1.05, "lh": 1.0, "reduce_lh_chords": true}
  ]
}
```

- 구간은 포함 마디 범위이며, 내부 시간 구간은 시작 포함·끝 제외다. 겹침·범위 밖·알 수 없는 필드를 거절한다. 여린내기는 단독 `"0"`으로 지정할 수 있다.
- `rh`, `lh`는 기존 셈여림·헤어핀·아티큘레이션 처리 후 적용하는 0–2의 유한한 재생 배수다. 생략한 손은 1이다. 0은 명시적 무음이다.
- `reduce_lh_chords`는 같은 시각에 **새로 시작하는 왼손 피아노 음의 수 N**에 대해 각 음의 배수를 `1/√N`로 조절한다. 여러 기보 성부를 함께 세며, 오른손·현악기·이미 유지 중인 음은 그 수에 넣지 않는다. 기본값은 false다.
- 계획이 없거나 구간 밖이면 기존 재생을 유지한다. 바이올린 등 현악기에는 적용하지 않는다.
- 실시간 재생과 WAV 저장은 같은 최종 `n.level`을 사용한다. MusicXML/PDF의 음표·음가·셈여림과 페달은 바꾸지 않는다. 실제 피아노 음향에 맞춘 보정이나 자동 루바토는 아니다.

`piece.build`가 계획을 검증·보존하고, `expression.playback`이 선택 필드로 전달한다. `listen_template.html`의 `applyPerformance`에서만 음량을 적용한다. 요청 전달·페이지 재작성에서도 `solo_score.json`의 계획이 유지된다.

이번 배수는 작성자의 청취용 선택이며 새 기본 계수가 아니다. 1–8마디 LH .85, 9–12 .95, 13–16 .90, 17–20 1.0, 21–24 .85, 25–28 .80, 29–32 .85다. RH는 17–20마디 1.05, 그 밖은 1.0이다. 모든 구간에서 왼손 동시 발음 완화를 켰다. B는 **반주와 음량을 함께 바꾼 비교**이므로 두 효과를 따로 측정한 실험은 아니다.

## 검증과 남은 판단

- Python 전체 266개 통과. 실제 브라우저 성능 함수를 Node에서 실행해 기존/중립 설정, 손·악기 구분, 구간 경계, 동시 발음 수, 음표 시각·길이 보존을 확인했다.
- XML 재읽기 일치, 실제 지속음을 포함한 왼손 최대 폭 12반음, 양손 교차 0. 두 악보 모두 오류 0.
- 솔로 경고는 6→7개다. 기존의 재현 추적 경고 1·강박 비화성음 미분류 5를 유지했고, 2박 양손 쉼을 사이에 둔 8→9마디를 기존 검사가 병행 8도로 보고한다. 쉼에서 비교를 끊는 윤곽 관찰의 LH 최저음·최고음 병행 완전음정 사건은 각각 0이다. 검사 범위를 구별하며 경고를 숨기지 않았다.
- 새 솔로 PDF 한 개, 1쪽 시각 확인. 공통 화성 PDF는 이전 파일 그대로다.
- 브라우저에서 A→B 자동 전환·정지, 음량 안내, XML/PDF/WAV 다운로드를 확인했다. HTTP 파일 25개 대조, 이전 전달본 18개 파일 해시 보존.
- 내려받은 WAV는 44.1kHz 모노, 91.929초(출력 꼬리 포함), 유효한 비무음 데이터이며 PCM16 최댓값 10,305, 포화 샘플 0이다. 음향 수치는 청취 품질 평가가 아니다.
- 기본 예제 XML와 원본 악보 해시 유지. 프로덕션 생성 기본값과 main은 변경하지 않았다.

작업 루트는 `K:\MusicGeneration\melody-research`. A는 `output/count-on-me/v003` / 전달 v001, B는 `output/count-on-me/v005` / 전달 v002다. v004는 종결부 내성 검토용 중간본으로 보존했다. 제작 스크립트는 `output/count-on-me/phrasing.py`, 비교·내성 기록은 `phrasing_comparison.json`과 v005의 `inner_voice_plan.json`, 최종 검증은 `phrasing-verification.json`에 있다. 음표·원본·PDF·WAV·반주 자료는 Git 제외 output에 둔다.

주제 자체의 추가 발전, 모든 세컨더리 화성의 로마자 분석, 루바토 구현은 이번 비교판의 범위에 넣지 않았다. 우선 같은 멜로디에서 반주의 호흡과 내성·재생 균형이 어떻게 들리는지 비교한다.
