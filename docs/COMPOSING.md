# 피아노 소품 작곡: 흐름과 파일 형식

요청 문장에서 새 피아노 솔로 곡을 만드는 틀입니다. 기존 `compose`/`text` 명령은 리드시트를 만들어 musicomp로 편곡하는 기준선입니다. 이 틀은 그와 별개로, **주제를 제시하고 발전시켜 완결하는 곡**을 피아노 악보로 바로 씁니다.

지금 단계에서는 대화 속 작곡자(클로드나 코덱스)가 요청을 해석하고, 설계와 악보 파일을 직접 씁니다. 프로그램은 다음을 맡습니다.

- 파일을 검증하고 악보(MusicXML, MIDI)를 만듭니다.
- 자동 검사를 하고 버전을 기록합니다.

언어 모델 연결은 다음 단계의 일입니다.

## 흐름

```
요청 문장
  │ 작곡자가 해석
  ▼
design.json   작곡 설계: 정서, 기본 조건, 주제, 형식, 구간별 계획, 절정, 끝맺음
  │ python -m musigen design <작업 폴더>     → 사용자에게 보여 줄 설계표(요청/제안 표시)
  │ (초기에는 사용자가 설계를 보고 고친 뒤 진행)
  ▼
score.json    악보: 동기, 마디 묶음별 오른손·왼손 재료(동기 변형, 직접 쓴 음, 복사, 반주 음형)
  │ python -m musigen piece <작업 폴더> --out output\<곡> --reason "<요청>"
  ▼
output\<곡>\v001\  piece.musicxml, piece.mid, checks.json, design.md, version.json
output\<곡>\history.md  버전마다 요청, 바뀐 마디(들어 볼 곳), 보존 약속 확인, 검사 결과
  │ 사용자가 듣고 말로 피드백 ("중간이 산만해요", "17마디부터 더 고조")
  ▼
작곡자가 피드백을 설계나 악보의 변경으로 옮김 → 같은 명령으로 v002 ... (--preserve로 지킬 것을 적음)
```

## 원칙(코덱스 검토 2026-10-23에서)

1. **요청과 제안을 구분합니다.**
   - 사용자가 정한 것은 `design.json`의 `given`에 적고, 나머지는 작곡자의 제안입니다.
   - 설계표에는 항목마다 "요청"이나 "제안"이 붙습니다.
   - 그래서 "쓸쓸한 느낌은 맞는데 너무 느리다"처럼 일부만 고칠 수 있습니다.
2. **설계가 먼저입니다.**
   - 마디별 계획은 음을 고정하는 것이 아니라 구간의 역할과 관계를 정하는 것입니다.
   - 예: "9–12마디는 a를 한 단계씩 올려 긴장을 쌓는다."
3. **주제 발전이 첫 목표입니다.**
   - 동기는 `score.json`에 한 번 적습니다.
   - 이후에는 변형 연산으로 불러 씁니다: 이동, 뒤집기, 늘이기, 조각, 리듬 유지/음 유지.
   - 모든 음에 출처가 남으므로, 검사가 "어느 구간에 어느 동기가 어떻게 나왔는지"를 보고합니다.
   - 주제는 왼손이나 둘째 성부(`rh2`, `lh2`)에도 둘 수 있습니다.
4. **수정은 들은 말로 받습니다.**
   - 버전마다 다음을 남깁니다: 요청 원문, 바뀐 마디, 설계에서 바뀐 항목, 보존 약속을 지켰는지.
   - 보존 약속은 `--preserve bars:1-8 motif:a`처럼 적습니다.
   - "처음 주제는 좋다"는 말은 `motif:a`와 그 마디의 보존으로 옮깁니다.
5. **첫 시험은 약 1분의 완결된 소품입니다.** 확인할 것은 세 가지입니다.
   - 요청 반영
   - 음악적 완결성(주제, 화성, 리듬, 형식의 연결)
   - 연주와 기보

   자동 검사는 박자, 음역, 손 벌림, 설계 대비 항목만 봅니다. 설득력은 듣고 판단합니다.

## design.json

필드 설명은 [musigen/design.py](../musigen/design.py) 맨 위에 있고, 예시는 [examples/pieces/after_rain/design.json](../examples/pieces/after_rain/design.json)입니다.

- `basics`
  - `meter`: 2/4, 3/4, 4/4, 6/8, 9/8, 12/8
  - `tempo`: 그 박자의 박 기준입니다(6/8이면 점4분음표).
  - `key`, `mode`: 조성과 장·단조
  - `grade`: 난이도 1–10급. 손 벌림과 동시음 수 검사에 쓰며, musicomp의 급수 표와 같습니다.
  - `length_sec`: 길이(초)
- `form`
  - 구간은 1마디부터 빈틈없이 이어집니다.
  - `function`: intro(도입), statement(제시), development(발전), contrast(대조), transition(연결), return(재현), coda(종결)
  - `motifs`: 그 구간에 나와야 할 동기입니다. 검사가 확인합니다.
- `climax.bar`: 오른손 최고음이 이 마디 ±1 안에 있어야 합니다. 검사가 확인합니다.
- `given`: 사용자가 정한 항목의 경로입니다. 예: `"basics.meter"`, `"form"`, `"form.1"`, `"ending"`.

## score.json

형식은 [musigen/piece.py](../musigen/piece.py), 음표 표기는 [musigen/notation.py](../musigen/notation.py), 동기 연산은 [musigen/motif.py](../musigen/motif.py), 반주 음형은 [musigen/accomp.py](../musigen/accomp.py)의 맨 위 설명에 있습니다.

- **음표**: `A4/q D5/q. E5/e | F5/h E5/e D5/e`
  - `|`는 마디 검사입니다.
  - `~`는 붙임줄입니다.
  - `[D3,F3,A3]/h`는 한 손 화음입니다.
- **동기**: `{"motif": "a", "ops": ["at:C5"]}`, `{"motif": "b", "ops": ["invert", "at:A5"]}`, `{"motif": "b", "durs": "q q q"}`
- **반주 음형**: `{"pattern": "broken", "chords": "Gm6:2 A7:1"}`. 음형은 block, bass, broken, alberti, waltz입니다.
- **복사**: `"copy": "1-4"`와 함께 쓰는 키입니다.
  - 다른 성부를 직접 주면 그 성부만 바뀝니다.
  - `"copy_ops": {"rh": ["oct:+1"]}`는 복사한 성부를 변형합니다.
- **조성 바꿈**: 묶음의 `"key": "F major"`는 그 묶음의 동기 연산과 철자를 정합니다. 조표는 곡의 것을 유지합니다.
- **셈여림과 글자**: `"dyn": "p"`, `"text": "rit."`

마디 길이가 맞지 않으면 묶음, 성부, 모자라거나 넘친 양을 알려 주는 오류가 납니다.

## 2026-10-23 P1 추가

`basics.pickup`은 4분음표 단위(숫자 또는 `"1/2"`). 여린내기는 0마디, form은 1마디부터이며 마지막 마디는 온마디다.
음표 뒤 `'` 스타카토, `>` 악센트, `_` 테누토를 하나만 쓴다. 붙임줄 음과의 조합은 거절한다.
`(C4/q D4/q E4/q)`처럼 한 재료 안에서 이음줄을 닫는다. retro와 frag에도 끝점이 보존된다.
score 최상위 `expression`은 `{"bars":"1-8","pedal":"bar","hairpin":"cresc"}` 형식이다.
페달은 bar/half/chord/held, 증감은 cresc/dim. 3/4의 half는 마디마다 갱신한다.
표현 기호 출력에는 musicomp `codex/xml-expression` 변경이 필요하다(병합 전 MUSICOMP_ROOT 지정).
위 '지금 없는 것' 목록 중 여린내기·표현 기보·브라우저 표현 재생은 P1에서 추가됐다.

## 주제 반복과 인식 (P2)

`{"motif":"a","ops":["at:C5"],"seq":{"times":3,"step":1}}`은 변형 후 세 차례 반복합니다. step 목록은 각 반복의 이동량, semi:true는 반음 단위입니다. delay:e는 앞에 쉼을 넣고 마지막 음을 줄이며, extend:q는 마지막 음을 늘리고, tail:C5,D5는 마지막 두 음만 바꿉니다. 블록의 길이는 정확히 맞아야 합니다. checks.recognition의 점수와 임계값은 잠정적인 악보 유사도이며 청취 인식률이 아닙니다.

## 음악 검사 (P3)

form의 선택 필드 cadence는 authentic/half/plagal/deceptive/none입니다. errors는 연주 불가, warnings는 설계 위반·분명한 검사 조건 위반, notes는 해석이 필요한 관찰입니다. 강박은 박자 단위 박 시작이며 6/8은 점4분음표 두 박을 검사합니다. 리듬 4마디, 구간 대비 2반음/15%는 잠정값입니다. 화음 기호가 없는 직접 기보 블록은 화성 검사를 미평가로 표시합니다.

## 피드백과 비교 (P4)

`piece --feedback "원문" --interpretation "작곡자가 바꾼 내용" --preserve bars:1-8 motif:a`로 변경 이력을 남깁니다. feedback 미지정 때 reason을 사용합니다. 바뀐 마디의 앞뒤 한 마디를 함께 듣는 비교 버튼은 부모가 포함된 듣기 페이지에서 동작합니다. --latest로 부모를 제외하면 비교할 수 없습니다.


## 프레이즈 설계와 관찰, 화성 표시 (2026-10-23)

`design.json`의 선택 필드:

```json
{
  "analysis": {"phrases": true},
  "phrase_plan": [
    {"bars": [1, 4], "role": "주제 제시", "plan": "a–b 동기 뒤 반종지, 마지막 박에서 쉼"},
    {"bars": [5, 8], "role": "응답", "plan": "주제 반복 후 으뜸화음 종지"}
  ]
}
```

분석을 켜면 `musicomp.analysis.motif.analyze_motifs(cross_check=False)`와 `phrase.segment_layers`를 기본 설정으로 호출합니다. 입력은 오른손 첫 성부의 실제 음·음가·쉼이며, 화성 추론을 경계 근거로 돌려 넣지 않습니다. 주선율이 화음이거나 겹치면 임의로 줄이지 않고 미평가 이유를 보고합니다. 여린내기의 실제 마디 번호 0을 유지합니다. 설계 범위는 온마디 1부터, 순서대로 겹치지 않게 적습니다.

`checks.phrasing`에는 실제 쉼, 자동 프레이즈, 끝 경계별 계획 일치 여부와 동기 관계가 들어갑니다. 계획과 결과가 다르면 작곡자가 음가·쉼·종지·주제 변형을 검토합니다. 분석 계수나 곡별 예외를 맞추지 않습니다. 아직 이 검사가 곡을 자동으로 다시 쓰지는 않습니다.

듣기 페이지의 Roman Numeral Analysis는 기존 화음에 대한 표기 분석입니다. 장·단·감·반감, 전위 숫자, 다음 화음으로 해결하는 반음계 딸림화음을 표시합니다. 첨가음·계류형은 괄호로 남기고 화음 밖 베이스는 별도로 밝힙니다. 전조 판단이나 경과 화음을 새로 추론하지 않으며, 음표·타이밍·다운로드 악보를 변경하지 않습니다. 일반 코드 표기의 버튼 이름은 Chord Symbols · 코드 심벌입니다.


## 모티프 교환 형식 (2026-10-23)

`score.motifs.a`에는 기존 음표 문자열 외에 다음 객체를 넣을 수 있습니다.

```json
{
  "format": "musicanote-motif",
  "version": 1,
  "name": "a",
  "events": [
    {"duration": "1", "pitches": ["F#4"]},
    {"duration": "1/2", "pitches": ["A4"]},
    {"duration": "1/2", "pitches": ["B4"]},
    {"duration": "1", "pitches": ["A4"]}
  ],
  "source": {"file": "my-score.musicxml", "part": "P1", "staff": "1", "voice": "1"}
}
```

duration은 4분음표 단위 양의 정수/분수 문자열, pitches는 철자가 있는 음이름 목록입니다. 빈 목록은 쉼입니다. 음가는 기존 writer가 지원하는 일반 음가와 셋잇단음표(1/12박 이상)로 제한하며 다섯잇단 등은 버림·반올림하지 않고 거부합니다. 가져온 모티프는 음악적으로 적합한 국소 조성을 정한 뒤 기존 연산에 넣습니다. 전조 악기에서도 기보 음높이 그대로 가져오며 실음 변환을 하지 않습니다.

구간 선택은 첫 선택 사건 시작부터 마지막 사건 끝까지입니다. 중간 시간 공백은 쉼으로 보존하고 선택 구간 안의 붙임줄은 합칩니다. 바깥으로 이어지는 붙임줄은 선택 경계에서 잘랐다고 보고합니다. 서로 다른 길이의 화음음, 일부 화음음만 붙임줄인 경우, 같은 성부의 음 겹침은 거부합니다. 반복을 펼치지 않으며 장식음은 제외 사실을 알립니다. 이음줄·페달·셈여림·아티큘레이션·가사는 이 교환 형식에 포함하지 않습니다. 표현은 새 작곡 설계에서 정합니다.

`source`는 원본 파일명·파트·보표·성부·시작/끝 마디와 박 위치를 담습니다. 외부 파일을 자동으로 다시 읽거나 경로를 실행하지 않습니다. 사용자가 붙여넣은 모티프를 그대로 주제로 사용할 때는 설계의 `given`에 `theme.motifs.a`를 기록하고, 새 음·반주·변형 계획은 작곡 제안으로 구별합니다.

CLI `motif --ops`는 기존 `realise`를 호출합니다. 미리보기 끝의 온마디를 채우기 위한 쉼은 `score.json`에만 더하며, 반환하는 `motif.json`은 원래 변형 길이 그대로입니다. 입력 모티프와 변형 목록이 출처에 남습니다. 모티프 가져오기와 발전은 선택 기능이며 기존 문자열 모티프의 출력은 유지됩니다.


## 페달 기호 표시와 자료 활용 신작 (2026-10-24)

`score.json`에 `"pedal_notation":"signs"`를 지정하면 Ped./* 기호로 출력합니다. 갈아 밟기는 *Ped.로 보이며 페달의 시간·재생·음표는 바뀌지 않습니다. 생략하거나 `"line"`이면 기존 선 표기입니다. 피아노 및 듀엣 출력에 적용합니다. Verovio 6.3에서 선 방식의 갈아 밟기 이후 페달이 보이지 않는 경우를 확인해, 이번 곡은 기호 방식을 선택했습니다.

새 피아노 소품 `examples/pieces/letter_on_the_breeze`는 「바람이 남긴 편지」(F장조, 4/4, 20마디, 약 63초)입니다. 쉼으로 시작하는 동기를 제시하고 음가 확대·하행 변형·재현·조각으로 발전시킵니다. 작성한 기본 패턴에서 기존 피아노 자료를 선택하려면 다음을 사용합니다.

```powershell
python -m musigen piece examples/pieces/letter_on_the_breeze --out output/breeze_rebuild --corpus-accompaniment
```

저장소의 예제는 새로 창작한 설계·주제와 기본 패턴입니다. 선택된 자료 반주는 생성 결과에만 저장됩니다. [자료 활용 범위와 제한](CORPUS_ACCOMPANIMENT.md)을 확인하세요.
