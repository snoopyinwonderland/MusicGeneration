# 인수인계: musigen 기틀 (2026-10-20)

이 문서는 다음 개발자(Astra)를 위한 것입니다. 지금 있는 것, 그렇게 만든 이유, 다음에 할 일을 적었습니다.

## 목표
사용자가 말로 요청하면 새 곡을 만듭니다. 요청에는 조성, 박자, 리듬, 형식, "몇 마디에서 어떻게"가 들어갑니다. 만든 곡은 musicomp로 편곡해 악보 품질을 들어 볼 수 있게 합니다. 사용자는 작곡가이고 결과를 들으며 판단합니다.

|---|---|---|
| `musigen/spec.py` | 작곡 명세(JSON) 정의와 검증. 모르는 필드는 거절한다 | 동작 |

## 설계에서 지킨 것
- **명세가 유일한 약속입니다.** 언어 모델은 명세만 채우고 음표는 만들지 않습니다. 같은 명세와 시드면 항상 같은 악보가 나옵니다. 그래서 문장 해석의 오류와 작곡 품질의 문제를 따로 볼 수 있습니다.
- **musicomp는 복사하지 않고 불러 씁니다.** `musigen/__init__.py`가 `MUSICOMP_ROOT`(기본: 옆 폴더 `Music Composition`)를 경로에 넣습니다. 화음 통계(`musicomp.analysis.harmonize_gen`), 철자(`musicomp.theory.spell`), 악보 읽기(`musicomp.core.score.load_melody`), 편곡(`musicomp.pipeline.arrange`)을 씁니다. musicomp를 고쳐야 하면 그 저장소의 `AGENTS.md` 절차를 따릅니다(브랜치 작업, 검수 후 병합).
- **리드시트는 musicomp 입력 형식 그대로입니다.** 선율 파트와 반주 화음 파트로 되어 있어, 사람이 만든 멜로디 악보와 똑같이 편곡됩니다. 사용자가 확인한 바로는 "멜로디 악보의 화성이 맞으면 피아노 솔로는 꽤 괜찮게 나옵니다". 그러니 작곡 쪽은 좋은 선율과 맞는 화음을 만드는 데 집중하면 됩니다.

## 알려진 한계
- **화성 리듬**: 마디당 화음이 하나뿐입니다. 전위 화음(슬래시 베이스)과 7화음 선택도 통계에 맡겨져 있습니다.
- **선율**
  - 동기 발전(반복·모방·sequence)이 없습니다. 홀·짝 마디가 리듬만 공유합니다.
  - 비화성음은 약박 경과음뿐입니다. 계류음·전타음·보조음의 역할이 없습니다.
  - 악구 안의 질문–대답 구조가 없습니다. 음역 윤곽은 단순한 아치입니다.
- **문장 해석**: 실제 모델로 시험하지 않았습니다. 정확도를 잴 평가 문장 세트도 없습니다.
- **박자**: 2/4, 3/4, 4/4, 3/8, 6/8, 12/8만 됩니다. 박자 변화와 못갖춘마디는 안 됩니다.

## 다음에 할 일 (권장 순서)
1. **선율 품질** (가장 중요)
   - 규칙 개선: 동기를 정해 반복·변형하고(음정 보존·리듬 보존·sequence), 악구 앞뒤를 질문–대답으로 만들고, 비화성음 종류를 늘립니다.
   - 학습 자료: musicomp가 쓰는 리드시트 1,400부와 Wikifonia 선율–화음 자료(`musicomp/knowledge`)에서 음정 진행, 리듬 n-gram, 종지 직전 음형을 집계해 가중치로 씁니다.
   - 모델: Anticipatory Music Transformer처럼 "정해진 화음과 마디 요구 안에서 빈칸을 채우는" 공개 모델을 미세조정하는 방안을 검토합니다. 개발 컴퓨터는 RTX 3000번대로 알려져 있으나 확인이 필요합니다.
   - 평가: 사용자 청취가 기준입니다. 보조 지표로 강박 화음음 비율, 음정 분포(리드시트 자료와 비교), 반복 구조 수를 냅니다.
2. **화성**: 마디 안 화음 변화, 종지 형태(카덴셜 6/4, 부속화음)를 넣습니다. musicomp의 Jazz 박마다 화성(`beat_slots`)을 참고합니다.
3. **마디별 다시 만들기**: "7–8마디만 다시"처럼 나머지는 고정하고 그 마디만 다시 생성합니다. 명세에 고정 구간을 두는 방식이 자연스럽습니다.
4. **문장 → 명세 평가**: 사용자가 실제로 쓸 법한 요청 문장 20–30개와 기대 명세를 만들어 모델 정확도를 잽니다. 사용자는 전에 Qwen 3.5 4B를 개발 컴퓨터 GPU로 썼습니다.
5. **작업 화면**: musicomp 작업 화면(`K:\Music Composition\workbench`)에 "새 곡 작곡" 탭을 붙이거나 별도 화면을 둡니다. 결과의 `arrangement/` 폴더는 이미 그 화면에서 열립니다.

## 작업 규칙 (musicomp에서 이어받음)
- **곡별 규칙은 만들지 않습니다.** 모든 수정은 어느 곡에나 적용되는 규칙이어야 합니다.
- **근거를 주석에 남깁니다.** 청취 의견 원문, 통계(분모 포함)를 규칙 옆에 적습니다.
- **전후를 비교합니다.** 숫자만으로 개선이라 단정하지 말고, 들어 볼 곳(폴더·마디)을 적습니다.
- **사용자에게 보이는 글은 한국어로 씁니다.**
- **저장소에 넣지 않는 것**: 생성 결과(`output/`), 저작권 악보, `.env`.
