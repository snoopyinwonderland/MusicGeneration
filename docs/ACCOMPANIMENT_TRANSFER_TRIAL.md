# 다른 모티프·박자의 반주 조건 비교

2026-11-11, `codex/accompaniment-transfer-trial`. 실험과 기술 검증은 완료했으며 청취 검수·기본 적용은 하지 않았습니다. [두 시험곡 감상](http://127.0.0.1:8804/index.html).

직전 6/8 비교에는 반주 계획뿐 아니라 9–10마디를 직접 고친 효과도 들어 있었습니다. 이번에는 두 곡 각각에서 **모티프·화성·직접 쓴 왼손·패턴 지시·표현·자료를 고정**하고, B에만 `accompaniment_plan`을 추가했습니다. 기존 검색기의 가중치, 반주 생성기, musicomp 코드는 바꾸지 않았습니다.

## 시험곡과 실제 자료 사용

| 곡 | 작성 입력 | 자료 참조 |
|---|---|---|
| 고요한 창가 · 반주 비교 | 기존 자작 시험 모티프와 16마디 설계, D단조·3/4·♩=76·약 38초 | 기존 TAVERN 악구 관찰을 작성 설계에 참조, musicomp 반주 자료 재사용 |
| 골목의 작은 걸음 | 이번에 새로 작성한 쉼으로 시작하는 모티프와 16마디, E♭장조·4/4·♩=92·약 42초 | 같은 악구 관찰을 참고하되 음·화성은 직접 작성, musicomp 반주 자료 재사용 |

4/4 곡은 6마디 C7(V7/ii)에서 Fm7으로 진행하고, 9–12마디는 C단조에서 주제 음가를 확대한 뒤 iv7–V7–i로 닫고 13마디에 E♭장조로 돌아옵니다. 이 조성 계획은 작성자 결정입니다. 새 DCML 관찰을 추출하거나 이 곡의 전조를 자동 학습한 것으로 기록하지 않습니다. 두 곡 모두 페달은 없습니다.

기존 학습 분할 피아노 라이브러리 924곡·왼손 76,929마디와 기존 밀도 모델(메타데이터 250곡·22,735마디)을 사용했습니다. A/B의 라이브러리·검색 코드·모델 지문은 같습니다. TAVERN의 사람 지정 악구 관찰과 이 곡의 작성 판단도 구별합니다. P3 자동 분절 통계 실패, P4 모델 중단, 자동 스타일 생성 보류를 바꾸지 않습니다.

## 결과

| 항목 | 3/4 A → B | 4/4 A → B |
|---|---|---|
| 왼손 3음·7음 생략 화성 구간 | 5/16 → 2/16 | 11/19 → 1/19 |
| 자료 반주 적용 마디 | 12/16 → 10/16 | 11/16 → 9/16 |
| 피아노 솔로 자동 검사 경고 | 0 → 1 | 1 → 2 |
| B 명시 요구 미충족 마디 | 14·15 | 14 |
| B 자료가 없어 작성 패턴 유지 | 14·15 | 6·14 |
| 직접 반주 보호 | 4·8·12·16 | 4·8·11·12·16 |

두 버전 모두 자동 검사 **오류는 0**입니다. 경고를 없앤 것으로 표시하지 않습니다. 3/4의 공통 멜로디+화성 요약 악보에는 15→16마디 병행8도 경고 1개가 양쪽에 같습니다. 4/4 공통 요약 악보에는 경고가 없습니다.

B에서 남은 구성음 생략은 모두 자료가 없어 돌아간 작성 알베르티 패턴입니다. 3/4의 14마디 Gm7에서 B♭, 15마디 A7에서 C♯, 4/4의 14마디 A♭maj7에서 C가 왼손에 없습니다. 이는 각 화음의 3음입니다. 해당 음이 오른손에도 없다는 뜻은 아닙니다. 4/4의 6마디는 작성 패턴으로 돌아갔지만 구성음 조건은 만족했습니다.

새로 늘어난 솔로 경고는 3/4의 14→15마디 병행8도와 4/4의 6→7마디 병행5도입니다. 따라서 **구성음 생략을 줄였다고 성부 연결까지 개선됐다고 할 수 없습니다.** 경고를 해석하거나 무시하는 새 계수·작품별 예외는 만들지 않았습니다.

실제 음표 변경은 3/4의 3·5·6·7·9·10·11·14·15마디, 4/4의 1·2·3·5·6·7·10·13·14·15마디입니다. 먼저 1–4, 9–12, 13–16마디를 듣고, 경고 구간의 앞뒤 마디를 비교할 수 있습니다.

사전 실현 조건 통과는 3/4에서 3,222/4,522, 4/4에서 956/1,245입니다. 이는 유형·역할 필터 이후 실제로 실현한 서로 다른 후보의 분모입니다. 전체 자료의 성공률이나 음악 품질 정확도가 아닙니다.

## 재사용 가능한 검증 명령

`musigen.accompaniment_trial`은 이미 생성한 결과 폴더를 검사합니다. 새 곡을 자동 작곡하거나 후보를 다시 검색하는 명령이 아닙니다.

```powershell
$env:MUSICOMP_ROOT = 'K:\Music Composition'
python -m musigen.accompaniment_trial --root output/transfer-v002
```

루트의 `trial_input.json`은 실제 `request`와 `cases` 목록을 갖습니다. 각 case의 `id`는 소문자/숫자/밑줄, `focus`는 들어 볼 곳입니다. `id/baseline`, `id/planned`에는 기존 `blueprint_solo` 결과와 PDF가 있어야 합니다. 입력 통제 검사는 `motif.json`, `development.json`, `realization.json` 전체를 비교하며 B의 `design.accompaniment_plan`만 차이를 허용합니다. A에는 켜진 계획이 없어야 하고, 작성 입력에 자료 반주 스냅샷을 넣지 못합니다.

모티프·음표·직접 반주·표현·화성·급수·출처가 달라지면 옵션만의 비교로 내보내지 않습니다. 실제 고정 MusicXML 음표 대조는 기존 `accompaniment_review.compare`를 사용합니다. 각 case의 `trial_case.json`, `comparison.json`, 루트 `trial_report.json`에 조건·관찰·경고·미충족 마디를 남깁니다. 이 명령은 청취 의견을 선택 기록으로 만들지 않습니다.

이번 로컬 입력과 출력: `K:/MusicGeneration/accompaniment-transfer/output/transfer-v002`. `output/build_inputs.py`, `generate_trials.py`는 이번 시험의 작성/생성 기록이며 Git에 넣지 않습니다. 이전 v001은 4/4 조성 범위 검수 전 중간판입니다.

```powershell
python -m http.server 8804 --bind 127.0.0.1 --directory output/transfer-v002
```

## 다음 개선 범위

1. 자료 후보가 없을 때 원래 패턴으로 돌아가는 과정에도 작성한 구성음 조건을 유지할 대안을 설계합니다. 현재처럼 미충족을 드러내되 조용히 다른 화음이나 선율로 바꾸지 않습니다.
2. 실제로 선택한 자료 마디와 작성 마디가 맞닿는 경계의 성부 연결을 함께 검사합니다. 마디별 조건과 원자료의 연속성만으로 이를 보장하지 못한 사례가 이번에 나왔습니다.
3. 위 변경은 같은 작성 입력에서 별도 선택 옵션으로 비교합니다. 이번 결과를 좋은 예제로 자동 편입하거나 기본값으로 승격하지 않습니다.
