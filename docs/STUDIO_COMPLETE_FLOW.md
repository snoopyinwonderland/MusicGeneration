# 저장한 모티프에서 완성 초안 받기

2026-11-11, 사용자 요청 “순서대로 다 진행하세요”의 세 번째 꾸러미입니다. 앞의 [내성 연결](INNER_VOICE_REVIEW.md), [새 주제 발전곡](MOTIF_DEVELOPMENT_STUDY.md)을 이어 입력 화면의 요청과 실제 악보를 연결합니다. 모델 호출이나 자동 스타일 변환은 추가하지 않았습니다.

## 사용하는 흐름

1. [모티프 입력과 작곡함](http://127.0.0.1:8806/)에서 JSON을 붙여넣거나 MusicXML의 선율 구간을 선택합니다.
2. 장면·정서, 조성·박자·빠르기·길이, 허용할 화성, 출력 종류를 정해 요청을 저장합니다.
3. 대화에서 “방금 저장한 요청으로 진행해 주세요”라고 전달합니다. 요청 파일을 읽고 모티프 발전과 상세 화성을 작성합니다.
4. 작성한 두 악보를 검증해서 전달하면, **목록 새로고침**으로 완성 초안을 확인합니다. 피아노 재생·XML·PDF·상세 왼손 화성 JSON·주제 발전 과정을 열 수 있습니다. 화성 악보만 요청한 경우도 지원합니다.

현재 작곡함에는 [오후의 편지](http://127.0.0.1:8806/requests/request-546102a21be34b7e9586d6a05c929635/results/v002/index.html)를 **작성 예제 · 사용자 선택 아님**으로 연결했습니다. 24마디 3/4, F장조→D단조→F장조, 4분음표=78, 약 55초, 페달 없음입니다. 원 출력 `afternoon-letter-v002`와 전달 버전 `results/v002`는 다른 종류의 버전이며, 전달 v002에서는 악보 제목·요청 원문·버전 표시를 바로잡았습니다. 음표와 PDF는 원 출력과 같습니다.

## 실행

```powershell
$env:MUSICOMP_ROOT='K:\Music Composition'
$env:PYTHONUTF8='1'
# 작업 트리 K:\MusicGeneration\motif-complete-flow 에서 실행
& 'K:\Music Analysis\.venv\Scripts\python.exe' -m musigen studio --out output/flow-v001 --port 8806
```

이미 8806 서버가 실행 중이면 다시 띄우지 않습니다. 작성 결과를 요청에 전달하는 명령은 서버와 별개이며, 웹에서 임의의 파일 경로를 받아 실행하지 않습니다.

```powershell
& 'K:\Music Analysis\.venv\Scripts\python.exe' -m musigen.studio_delivery `
  --root output/flow-v001 `
  --request request-546102a21be34b7e9586d6a05c929635 `
  --piece output/flow-v001/afternoon-letter-v002
```

재실행은 v003, v004처럼 새 전달 버전을 만듭니다. 이전 결과를 덮어쓰지 않습니다. `output/`과 악보·원자료는 Git에 넣지 않습니다.

## 검사와 범위

- 저장한 **전체 모티프 JSON**의 지문을 비교합니다. 이름·출처를 포함한 변경도 새로운 입력으로 취급합니다. 첫 제시의 음높이·리듬·쉼 보존은 기존 `prepare`에서 검사합니다.
- 요청 조성·박자·4분음표/분·마디 수를 비교하고, 실제 MusicXML 양손의 음·철자·성부·음가·화성·조표·빠르기·박자·마디 수를 다시 확인합니다. 6/8의 점4분음표 템포와 입력의 4분음표 템포를 혼동하지 않습니다.
- 전조·증6화음·세컨더리 화음을 허용하지 않은 요청을 검사합니다. 세컨더리는 작성 기능 기호 외에 일반 코드 심벌의 분석도 확인합니다. 정서·작곡가 스타일의 성공 여부를 자동 인증하지 않습니다.
- 오류가 있거나 요청한 PDF가 없으면 전달하지 않습니다. 경고는 숨기지 않고 두 악보별로 표시합니다. 새 곡의 솔로는 오류·경고 0, 화성 요약은 병행5도 경고 4개(2·12·14·23마디)입니다.
- PDF는 전달할 때 파일 표식·존재·지문을 검사합니다. PDF 음표의 의미를 자동 대조하는 것은 아니며, 이번 실제 PDF는 별도로 렌더링해 시각 검수했습니다.
- 미리 작성된 듣기 페이지를 그대로 믿지 않고 검증한 악보·검사 결과로 다시 만듭니다. 작성 과정과 명시 내성 보고서도 다시 계산합니다. 참조 라이선스·출처 JSON을 함께 보관합니다.
- 전달 기록에 요청 지문·파일별 지문·버전·경고를 남기고, 카탈로그 조회에서 바뀐 파일을 발견하면 결과 링크를 숨깁니다. 이전 버전은 그대로 남고 새 요청/결과가 자동 청취 승인되지는 않습니다.

테스트 238개 통과. 별도 QA 서버에서 예시 입력→저장→대기 목록, 잘못된 입력의 저장 차단을 확인했습니다. 실제 작곡함에서 두 악보 표시·재생 상태·로마자 표기·다운로드·390px 화면(가로 넘침 없음)을 확인했습니다. HTTP 18개 정상, 외부 Origin 요청 403, 잘못된 JSON 요청 400입니다. 기술 검증을 청취 평가와 구분합니다.
