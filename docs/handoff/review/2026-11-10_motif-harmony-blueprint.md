## 요청과 구현

사용자: “짧은 멜로디를 입력 받으면 그걸 발전시켜서 한 곡의 멜로디 + 화성(왼손) 악보 / 피아노 솔로 두 버전으로 만드는 것입니다.” “왼손 화성 정보는 최대한 상세해야 합니다.”

새 `blueprint` 명령은 모티프와 대화에서 작성한 발전 설계를 받아 오른손 단선율 + 전체 구성음을 가진 왼손 요약 악보를 만듭니다. 선택적으로 기존 musicomp 검색 편곡을 호출합니다. 이전 곡별 예외나 새 화성 인식 규칙을 추가하지 않았습니다. 기존 `piece`/`compose`는 그대로입니다.

모티프만으로 자율 작곡하는 모델, 가사·정서 학습, 검수된 종지 자료 검색은 아직 구현하지 않았습니다. 이번 꾸러미가 완료되어도 그 후속 작업을 완료로 보지 않습니다. 반려된 P2 p1–p4를 승인된 것으로 기록하지 않았으며 원래 P2 완료 주장도 하지 않습니다.

## 한계와 위험

1. 입력은 단선율·단일 조성·단일 박자·온마디 시작입니다. 직접 쓴 왼손, 페달·표현 span, 국소 전조는 거부합니다. 지원하지 않는 코드도 조용히 바꾸지 않습니다.
2. `harmony.json`의 기능·종지·정서·출처·보이싱 의도는 아직 musicomp가 읽지 않습니다. 전달을 검증한 것은 MusicXML의 선율·시점·구성음·베이스입니다. 연주 배치나 모든 구성음의 독주 유지 보장은 아닙니다.
3. 로마자는 기보된 코드 기준 표시입니다. 종지 라벨은 검증되지 않은 작곡자 의도로 명시합니다. 첨가음/비화성 베이스는 잘못된 전위 숫자로 표시하지 않습니다.
4. 독주 출력에는 화성 기호가 없어 해당 페이지 Roman 버튼은 비활성입니다. 표현 재생은 기본값이며 독주 XML의 모든 표현을 추출하지 않습니다. 이 초안에는 페달이 없습니다.
5. PDF는 첫 초안에 별도 생성·연결했습니다. CLI의 자동 PDF 렌더링은 미구현이며, 페이지 생성 시 이미 있는 PDF만 포함합니다. Verovio 로컬 설치가 없으면 기존 CDN을 사용합니다.
6. `--arrange`는 musicomp의 기존 파이프라인을 호출하므로 추가 앙상블 파일도 생성하지만 이 꾸러미의 검수 대상은 두 피아노 악보입니다. 보고서의 앙상블 경고를 독주 오류로 혼동하지 않아야 합니다.
