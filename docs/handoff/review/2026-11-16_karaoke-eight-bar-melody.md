# 노래방 자료를 사용한 8마디 선율 검수 요청

브랜치 `codex/karaoke-eight-bar-melody`, 기준 커밋 `68512d7`. 사용자는 민요 기반 후보 대신 노래방 데이터를 지정하고 8마디 멜로디를 요청했다. 이번 요청에 명시한 자료 범위에서 로컬 KYSing 보컬 MIDI를 읽었다. 원자료와 생성 악보는 `output/`에만 둔다.

[51번 「말하지 못한 오후」 듣기](http://127.0.0.1:8808/melody-phrases/karaoke-eight-bar.html). G장조, 4/4, 분당 88박, 약 22초. 선율만 피아노 소리로 재생하며 MusicXML·MIDI 받기를 제공한다. 8808 작품 목록의 첫 항목에 연결했다. 이전 41–50번은 그대로 보존한다.

## 작성과 출처

기존 `source_windows`가 읽는 S1/channel 4 보컬에서 연속 2마디를 추출한다. 리듬과 음높이의 출처는 서로 다르며 원 리듬과 같은 결합은 거절한다. 각 구간은 7–9개 음 전체의 순서를 보존한다. 1–6마디는 상대 음정도 보존하고, 7–8마디는 음높이를 새로 썼다.

| 출력 | 리듬 출처 / 시작 4분음표 위치 | 음높이 출처 / 시작 위치 | 처리 |
| --- | --- | --- | --- |
| 1–2 | 사랑의 바보 / 67 | My Love (And) / 20 | 원 음높이 유지, 제시 |
| 3–4 | My Love (And) / 28 | 천상연 / 20 | 전체 -4반음, 4마디 뒤 2박 쉼 |
| 5–6 | 사랑의 바보 / 67 | 나는 반딧불 / 224 | 전체 +2반음, 첫 리듬을 되받고 E5 도달 |
| 7–8 | Golden / 295 | 새로 작성 | 8마디 G4를 3박 유지하고 1박 쉼 |

이 표의 위치는 파일 시작부터 센 MIDI 시각이며 인쇄 마디 번호가 아니다. 상세 tick·파일 SHA256은 레시피에 있다. 기존 16분 격자 양자화 허용 오차와 온전한 음만 추출하는 조건을 사용한다. 32개 발음 중 25개의 음높이는 출처 구간에서, 7개는 새 종결에서 온다. 마디선에 걸친 음가는 붙임줄로 표시한다.

이번 배치는 작성자가 후보를 확인하여 고른 것이다. `join_cost`는 사후 진단으로만 사용했다. 세 경계의 비용은 0.835, 2.25, 1.835이며 가운데 값에는 의도한 2박 호흡이 포함된다. 최소 비용 자동 작곡이나 모델 학습으로 설명하지 않는다.

## 변경 파일과 재현

- `examples/karaoke-eight-bar.json`: 출처 파일·해시·2마디 위치·이조·새 종결 음높이만 기록. 원곡 음표는 포함하지 않는다.
- `scripts/karaoke_phrase_study.py`: `resolve`가 원자료와 해시를 확인하고, `build`가 명시적 레시피를 기존 `combine`으로 기보한다. 기본 생성 엔진은 변경하지 않는다.
- `docs/MELODY_LISTENING_FEEDBACK.md`: 민요 대신 노래방 자료를 요청한 최신 의견 기록.
- 로컬 `output/karaoke-eight-bar/`: 탐색 자료, 악보, 미리듣기 일정, 출처 검증과 테스트 로그. `output/melody-studio/`에 감상 페이지와 목록을 갱신했다.

저장소를 PYTHONPATH에 넣고 지정 Python에서 다음을 실행한다. 출력 파일은 새 파일이어야 한다.

```powershell
python scripts/karaoke_phrase_study.py examples/karaoke-eight-bar.json --out output/karaoke-eight-bar/recheck.json
```

## 검증과 남은 범위

원 MIDI에서 선택 구간을 다시 추출해 리듬과 음높이를 대조했다. 생성 MusicXML을 재파싱해 8마디·32박·32발음과 붙임줄을 확인했다. 선택한 다섯 곡의 전체 보컬과 비교한 12음 연속 음정+리듬 일치는 0건이었다. 전체 데이터베이스나 청취상 유사성을 검증한 결과는 아니다.

브라우저에서 악보를 시각 확인하고, 피아노 재생 시작부터 완료 상태까지 확인했다. 전체 테스트 274개 중 273개 통과, 기존 `test_phrase_observations_have_real_breaths_and_all_notes` 1개 실패가 반복됐다. 외부 musicomp 분절이 기존 기대 6구절 대신 4구절을 반환하는 이전부터의 차이이며, 외부 엔진과 해당 테스트는 수정하지 않았다.

음악적 선호는 사용자 청취 대기다. 반주·새 화성·전체 곡 확장은 이번 출력에 포함하지 않는다. main에 push하지 않는다.
