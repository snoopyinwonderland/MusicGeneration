## 문제와 최종 동작

`compose --arrange`와 달리 `piece` 소품 경로는 작성한 단순 반주 패턴만 사용했다. 새 `piece --corpus-accompaniment`는 작곡된 선율·화성·프레이즈·구간을 musicomp에 전달하고, 기존 자료의 왼손 음형과 밀도 모델을 사용한다. 원래 반주와 후보를 기존 분류기로 같은 유형으로 분류한 범위에서 검색한다. 반주 유형·박자·화음 변화 위치가 맞는 후보가 없거나 연주 조건에 맞지 않으면 해당 마디의 기존 반주를 유지한다.

오른손 두 성부, 동기, 화성, 쉼, 페달·셈여림은 유지한다. 직접 쓴 왼손·둘째 성부·마디를 넘는 지속음도 보호한다. 실제 반주 음표를 `score.json`에 고정 저장해, 다시 열거나 듀엣으로 변환할 때 검색을 반복하지 않는다. 입력 설계/악보가 바뀐 낡은 스냅샷은 거절한다.

## 변경 파일·함수

- `musigen/corpus_accomp.py`: `semantic`(작곡 데이터 어댑터), `PlannedFigures`(기존 음형 분류기의 후보 제한), `select`(검색·실현·검사·출처), `apply_snapshot`(재현)
- `musigen/piece.py:build`: 저장된 반주 스냅샷 적용
- `musigen/__main__.py:main`: `piece --corpus-accompaniment`
- `musigen/versions.py:save`: 별도 `accompaniment.json` 보고서
- `tests/test_corpus_accomp.py`: 14개 회귀 검사
- `docs/CORPUS_ACCOMPANIMENT.md`, `README.md`: 사용법·자료 범위·제한

musicomp와 Music Analysis 코드, main 작업 폴더, 공개 페이지, 음원 파일은 수정하지 않았다. 곡별 예외나 검색 계수 조정은 추가하지 않았다.

## 위험과 후속 범위

1. 연결한 것은 반주 후보 자료·밀도 모델이다. 주제 생성/발전, 새 화성 계획, 전체 미학을 학습한 작곡 모델은 아니다.
2. 분류기는 큰 음형 범주만 보존한다. 왈츠를 block으로 묶거나, 재실현 시 일부 음이 빠져 원자료의 세부 음형이 변할 수 있다. 손에 맞지 않으면 원래 반주로 돌아가며, 더 좋은 다음 후보를 자동 재검색하지 않는다.
3. 전체 검색 비용은 오른손 채움 정보도 참고하지만 이번 출력은 원래 오른손을 보존한다. 피아노 전체 편곡 경로의 품질을 그대로 기대하면 안 된다.
4. 오른손 첫 성부의 화음/음 겹침과 완전히 빈 프레이즈는 현재 지원하지 않는다. 묵시적으로 선율을 추출하거나 원래 음을 버리지 않는다.
5. 자동 검사 경고는 후보를 전부 탈락시키는 장치가 아니다. Nostalgic의 남은 경고와 접속부 청취를 먼저 검수하고, 이후 기존 검사 기반 후보 재선택을 별도 꾸러미로 검토한다.
6. 생성 결과를 학습 데이터로 자동 환류하지 않는다. 사용자 청취 평가, 실패 유형, 자료 출처를 축적한 후 검수된 예제만 다음 자료 개선에 사용해야 한다.
