# 자료 기반 리듬 배치와 음높이 실현 검수

브랜치 `codex/corpus-rhythm-first`, 기준 `4df32fa`. 사용자는 여러 음악에서 음형·리듬을 가져와 연결 비용으로 배치한 다음 음높이를 입히도록 요청했다.

[걸음을 잇는 노래](http://127.0.0.1:8808/listen/rhythm-first/v001/index.html#piece=rhythm_first&version=v001)는 C장조 4/4, 16마디, ♩=112의 첫 단선율 실험이다. 상단 선택 상자에서 같은 음높이의 ‘리듬만 듣기’로 전환할 수 있다. 선율판에는 MusicXML·PDF·피아노 샘플 WAV 받기가 있다. 이전 청취 기준은 [한 걸음 늦게 v002](http://127.0.0.1:8808/listen/phrase-first/v002/one_step_late.html#piece=one_step_late&version=v002)다.

## 구현과 근거

`musigen/rhythm_retrieval.py`를 선택 실행하는 새 경로로 추가했다.

- `extract`는 MTC-ANN 360곡의 명시 프레이즈 경계를 읽어 4/4 두 마디에 들어가는 후보 100개를 확보했다. 음 시작 간격, 음 길이, 구간 안 쉼과 원곡의 박 위치를 보존한다. 끝음 이후 두 마디 끝까지 붙인 여백은 `padded_tail`로 별도 기록한다. 원곡의 음높이는 상승·하강·동음 방향으로만 바꿔 배치 단계에 넘긴다. 원자료 경로·SHA-256·곡 ID·프레이즈 번호·음 인덱스를 보고서에 남긴다.
- `join_cost`는 앞 구간 끝과 다음 구간 시작 사이의 무음, 끝/시작 세 간격의 중앙값 비율, 단위 박당 발음 수 차이, 인접 구간의 동일 리듬을 계산한다. 총비용은 무음 1박 초과분 + 간격 비율의 절대 log2 + 밀도 차이 + 동일 리듬 0.5다.
- `arrange`는 전체 경로 후보 48개를 유지하는 빔 탐색이다. 배치 비용은 구간별 목표 밀도와의 차이, 시작까지 여백/4, 세 번째 이후 같은 리듬 사용 횟수를 합한다. 이번 목표 밀도는 1.5, 1.25, 1.75, 1, 1.5, 1.75, 1.25, 1 발음/박이다. 사용자 요청의 ‘연결 비용’에 대한 초기 설계이며 청취로 학습된 가중치는 없다. 전체 최적해 보장은 없다.
- `fit_pitches`는 배치된 리듬 위에서 C장조 음역 D4–G5와 미리 작성한 16마디 화성을 사용해 동적계획법으로 음높이를 선택한다. 원곡의 방향 변화, 인접 음의 이동, 강박/긴 음의 화음 구성음과 마지막 도착음을 비용에 반영한다. 화성 계획과 목표 밀도는 이번 실험의 수동 설계다.
- `notation`은 선택된 리듬을 음높이와 결합해 기존 악보 문법으로 넘긴다. 파일 실행 옵션은 `--source`와 `--out`이며 출력 폴더는 새 경로를 받는다.

## 선택 결과

| 배치 마디 | 리듬의 원곡/프레이즈 |
| --- | --- |
| 1–2, 5–6 | NLB070475_01 / 1 |
| 3–4, 7–8 | NLB070475_01 / 3 |
| 9–10 | NLB072441_01 / 3 |
| 11–12 | NLB073031_01 / 1 |
| 13–14 | NLB072441_01 / 2 |
| 15–16 | NLB070526_01 / 5 |

네 곡의 여섯 프레이즈를 사용한 여덟 구간이다. 처음 네 마디의 리듬이 5–8마디에서 돌아오며, 화성에 맞춰 음높이가 바뀐다. 경로 비용은 1.75다. 낮은 연결 비용은 청취 선호를 의미하지 않는다. 연결 비용이 밀도와 간격의 연속성을 선호하므로 대비가 부족해질 수 있다.

이번 자료는 네덜란드 가창 선율의 명시 경계를 가진 코퍼스다. 전체 DB의 리듬을 모두 후보로 수록한 상태는 아니다. 다음 코퍼스 확장은 기보 박자·약박 시작·프레이즈 경계를 검증한 자료부터 추가해야 한다. 연주 초 단위 MIDI를 기보 박으로 직접 취급하지 않는다.

## 검증

- `tests/test_rhythm_retrieval.py`에서 원곡 약박 시작·내부 쉼·길이 보존, 경계 공백 비용, 음높이 부착 후 리듬 일치와 기보, 다중 곡 배치와 비용 합계를 검사했다. 전체 270개 테스트 통과.
- 원자료에서 선택된 모든 음의 시점·길이와 출력 악보의 리듬이 일치한다. MusicXML 재읽기의 음높이·시점·길이도 일치한다.
- 자료 및 이전 출력 791,135개 성부에 대한 연속 12음 일치/16음 근접 검사에서 0건이다. 긴 연속 구간 검사 범위 안의 결과이며 의도적으로 빌린 리듬과 방향은 보고서에 표시했다.
- PDF 한 페이지를 시각 확인했다. 내장 브라우저에서 선율 및 리듬 단독 모드의 피아노 재생·정지·선택 전환을 확인했다.
- 검수 대상 파일은 새 모듈, 회귀 테스트, 이 요청서다. 생성물과 원곡 자료는 Git 제외 `output/rhythm-first`에 있다. 음표를 직접 작성하던 이전 경로와 함께 선택적으로 실행할 수 있다.

## 재실행

```powershell
$env:MUSICOMP_ROOT = 'K:/Music Composition'
$env:PYTHONUTF8 = '1'
& 'K:/Music Analysis/.venv/Scripts/python.exe' -m musigen.rhythm_retrieval --source 'K:/Music Composition/data/external/mtc/MTC-ANN-2.0.1_sequences-1.1.jsonl.gz' --out output/rhythm-first-new
```

선택 보고서 `report.json`, 악보 입력 `score.json`, 중복 검사 입력 `queries.json`을 생성한다. 이번 MusicXML·PDF·청취판을 출력한 로컬 스크립트는 `output/rhythm-first/render.py`와 `publish.py`다.

새 출력 폴더에서 재실행한 악보와 검사 입력이 동일하고, 함께 생성한 design.json과 score.json을 기존 piece.build가 읽어 16마디를 구성하는 것을 확인했다.
