# 검수 요청: Nostalgic Piano Solo — 제공 모티프의 발전

- 날짜: 2026-10-23
- 브랜치: `codex/nostalgic-piano-solo`
- 기준 커밋: `b7cddb4` (화성 모드·위치 기억 포함)
- 상태: 곡 초안 및 자동·화면 검증 완료. 청취 승인 및 main 기본 적용은 아님.

## 요청과 범위

사용자가 붙여 넣은 `musicanote-motif` v1 데이터를 이용해 “Nostalgic Piano Solo를 만들어 보세요.”라고 요청했다. 출처 메타데이터는 `Smoke Gets in Your Eyes.xml`, P1/staff 1/voice 1, 9–11마디다. 원형 선율을 독창적으로 새로 작곡했다고 주장하지 않는다. 추가 선율·발전·화성·반주는 Codex가 구성했다.

소프트웨어 함수·기본값·규칙은 변경하지 않았다. 새 악보·음원·입력 데이터는 AGENTS.md에 따라 ignored `output/`에만 보관한다. 이번 커밋은 이 검수 요청서만 포함한다. main 및 MusicAnalysis/musicomp는 수정하지 않았다.

## 음악 설계와 들어 볼 구간

Eb 장조, 4/4, 4분음표=64, 피아노 솔로 16마디/60초, v001. 입력은 반주 없는 3마디/12박/11음이며 결과는 이 모티프를 중심으로 만든 16마디 소품이다.

| 마디 | 시간 | 구성 |
|---|---|---|
| 1–4 | 0–15초 | 원형 3마디 보존, 하행 응답과 쉼 |
| 5–8 | 15–30초 | 첫 조각의 이조와 둘째 조각의 응답, 반주 리듬 변화와 두 박 여백 |
| 9–12 | 30–45초 | 첫 조각을 한 옥타브 올리고 음가를 두 배 확대, 종결음 조정, F5 절정 |
| 13–16 | 45–60초 | 원형 회상, Abm6의 단조 색채와 Eb 장조 종결 |

반주는 기존 broken/waltz/shell 패턴을 사용했다. waltz 패턴 명칭은 구현상의 이름이며 박자는 4/4다. 주선율 쉼은 4·7·8·12마디 총 4곳/4.5박이다. 페달과 p–mf–pp 강약, 크레셴도·디미누엔도를 포함했다.

## 산출물

모두 로컬 `K:\Music Generation-codex\output\nostalgic-piano-solo\` 아래에 있다.

- `work/motif.json`: 사용자 입력 및 출처
- `work/design.json`, `work/score.json`: 재생성 가능한 작곡 설계·악보 입력
- `piece/v001/`: 버전 기록, MusicXML, MIDI, PDF, 마디별 정보, 검사
- `listen/piece/v001.html`: 악보별 감상 페이지. 악보 엔진·피아노 샘플·PDF를 내장
- `Nostalgic Piano Solo.musicxml`, `Nostalgic Piano Solo.pdf`, `Nostalgic Piano Solo.wav`: 브라우저 다운로드 버튼으로 저장한 결과
- `Nostalgic Piano Solo-출처.txt`: 모티프 및 피아노 샘플 출처
- `qa/`: 브라우저 검사 JSON, 원형 보존 검사 JSON, 데스크톱/모바일 화면

감상 주소: `http://127.0.0.1:8787/piece/v001.html` (이 컴퓨터의 미리보기 서버가 실행되는 동안). 서버는 loopback에만 바인딩한다. 종료 후에는 다음 명령으로 다시 열 수 있다.

```powershell
& 'K:\Music Analysis\.venv\Scripts\python.exe' -m http.server 8787 --bind 127.0.0.1 --directory 'K:\Music Generation-codex\output\nostalgic-piano-solo\listen'
```

공개 GitHub Pages에는 이번 모티프/악보를 게시하지 않았다. 이 문서만으로는 악보를 재생성할 수 없으며 로컬 사용자 입력 파일이 필요하다.

## 검증

- MusicXML에서 1–3마디와 13–15마디의 주선율을 사용자 입력과 비교: 각각 11/11음 음높이·음가 일치, 12박.
- musicomp 프레이즈 분석 기본값: 1–4, 5–8, 9–12, 13–16마디 검출. 설계 끝 지점 4/4 일치. 자동 관찰이며 음악적 완성도 판정은 아님.
- 악보 검사: 오류 0, 비화성음 경고 2. 손 교차·손 폭 경고 없음.
- PDF 1페이지. Poppler PNG로 전 페이지를 눈으로 확인: 보표·쉼표·페달·강약·페이지 번호 겹침이나 잘림 없음.
- 브라우저: Verovio 로그 및 pageerror 0, 피아노 버퍼 30개, 재생 음표 154개, 길이 60초, 페달 시작/끝 표시 32개.
- Chord Symbols ↔ Roman Numeral Analysis 전환: 16개 기호 일치, 재생 음표/시간 불변, 재생 유지. 화면 화성 위치는 보표 아래. PDF/XML은 기존 동작대로 원본 기호 위치를 유지한다.
- 9–12마디 선택 재생: 30–45초 구간 일치.
- XML/PDF/WAV 실제 다운로드 성공. WAV 44.1kHz, 60.5초(잔향 포함), peak 0.36694, RMS 0.03935: 무음·디지털 클리핑 없음. 직접 청취에 의한 음질/음악성 승인을 의미하지 않는다.
- 데스크톱 1440px 및 모바일 390px 확인, 가로 넘침 없음.
- Python unittest 72개 통과, Node 페달 재생 테스트 4개 통과. 최초 샌드박스 실행은 임시 폴더 권한으로 11개 오류가 났고, 정상 권한으로 다시 실행해 전부 통과했다.

## 청취 검수와 위험

- 5마디 F4/Cm7, 6마디 G4/Fm7: 자동 분류에서 해결 형태 미분류 경고가 남는다. 각각 모티프의 이웃음 진행 및 9도 색채로 의도해 유지했으며 자동 통과로 숨기지 않았다. 이 두 곳의 긴장과 해소를 들어 볼 것.
- 9–10마디는 원형의 완전한 기계적 확대가 아니라 마지막 음을 조정한 변형이다.
- 15마디 Abm6 및 Cb5→Bb4 내성의 쓸쓸한 색채가 과한지, 16마디 종결이 충분한지 확인할 것.
- 피아노 샘플과 페달 모델을 사용한 검수용 렌더링이며 실제 연주자의 루바토·페달 연주를 재현하지 않는다.
- 사용자 제공 모티프의 출처와 추가 구성의 저자를 구분해 감상 페이지에 적었다. 악보와 출력은 저장소에 넣지 않는다.
