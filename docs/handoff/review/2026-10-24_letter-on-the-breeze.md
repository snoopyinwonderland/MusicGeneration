## 곡과 자료 사용

「바람이 남긴 편지」는 이번 대화에서 Codex가 새로 구성한 피아노 솔로다. F장조, 4/4, 4분음표=76, 20마디, 약 63.16초. 기존 작품 모티프는 입력으로 사용하지 않았다. 제목·주제·형식·화성은 작곡 제안이고, 피아노 솔로와 기존 데이터 활용이 사용자 요청이다.

- a: 반 박 쉼 뒤 A–C–D–E–C. 순차 상행을 포함한 짧은 인사.
- b: F–A–G–F 뒤 한 박 쉼. a에 응답.
- 1–8마디: 제시와 응답. 4마디 반종지, 8마디 정격종지와 양손 두 박 쉼.
- 9–12마디: a의 음가를 두 배로 늘린 회상, 11마디 A5 정점에서 같은 리듬을 하행형으로 바꿈.
- 13–16마디: 주제 원형과 알베르티형 반주의 재현, 양손 두 박 쉼.
- 17–20마디: a의 앞 조각과 b의 답장, 정격종지.

병합된 `corpus_accomp.select`를 그대로 호출했다. 실제 인덱스는 924곡·76,929개 왼손 마디이며, 기존 250곡·22,735마디 학습 밀도 모델도 사용했다. 이번 곡에서는 **7개 출처 곡의 자료를 16마디**에 적용했다. 출처·마디·검색 이유·밀도 목표·해시는 출력의 `accompaniment.json`에 있다.

적용: 1–7, 9–15, 17–18마디. 8·16마디의 쉼과 19–20마디의 직접 쓴 종결은 보호했다. 기본 패턴판 대비 오른손·주제·화성·표현 계획은 동일하고, 왼손 이벤트 수는 98→76이다. 자료를 사용하는 것은 왼손 반주 검색·실현이며, 주제 생성이나 전체 곡을 학습 모델에 맡긴 것은 아니다.

## 페달 표기 보완

처음의 선 표기는 Verovio 6.3에서 7마디 `change` 이후 그려지지 않았다. SVG 요소 수는 42개였지만 뒤 요소는 자식 경로·경계가 비어 있었다. 음원과 XML의 페달 타이밍 자체는 남아 있어, 요소 개수만 세는 검사가 놓치는 문제였다.

선택 옵션 `score.json`의 `"pedal_notation": "signs"`를 추가했다. 페달의 `type`, `offset`, 보표와 연주 데이터는 그대로 두고 MusicXML 페달 속성만 `line="no" sign="yes"`로 내보낸다. Ped./*와 갈아 밟는 *Ped. 기호가 42개 모두 실제로 표시되는 것을 확인했다. 기존 기본값 `line`과 기존 악보 바이트는 유지한다. 이 옵션은 피아노 악보와 향후 듀엣 출력에서 함께 보존한다. musicomp는 수정하지 않았다.

## 변경 파일·함수

- `examples/pieces/letter_on_the_breeze/design.json`, `score.json`: 새로 창작한 설계·동기·기본 반주. 자료 검색 결과나 출처 악보는 넣지 않음.
- `musigen/piece.py:Piece, build`: 페달 표시 옵션과 유효성 검사.
- `musigen/piano_io.py:write_musicxml, pedal_notation`: 출력의 페달 표시 속성만 선택적으로 변환.
- `musigen/duet.py:write_duet`: 같은 표시 옵션 적용.
- `tests/test_notation_expression.py`: 선/기호 모드의 음표·시간·연주 동일성, 갈아 밟기, 듀엣의 표시 유지, 잘못된 옵션 거부.
- `docs/COMPOSING.md`: 표시 옵션과 이번 곡 사용법.

## 검증

- Python 전체 검사 **92개 통과**. 기존 악보 바이트 회귀 통과.
- Node 재생 검사 **6개 통과**.
- 최종 곡 자동 검사 오류 0, 경고 0. 보존 약속 위반 0. 최고음은 설계대로 11마디 A5.
- 선율 쉼 합계 15개의 4분음표 길이(약 11.84초). 프레이즈 분석 호출. 계획한 4·8·12·16·20마디의 끝은 하위 프레이즈에서 관찰되지만, 상위 자동 분할은 2·8·14·18·20마디로 달랐다. 계획 일치나 분석 정확도를 과장하지 않는다.
- 실제 Chrome: 페이지 오류·Verovio 로그 0, 피아노 샘플 30개 로드, 166개 재생 음표. 화성 표시 전환 전후 음표 시간/길이/높이 유지.
- 페달 요소 42개 모두 비어 있지 않은 SVG 경계 확인(42/42). 단순 요소 개수 검사에 그치지 않음.
- MusicXML/PDF/WAV 실제 다운로드 성공. WAV 44.1kHz, 약 63.66초(여운 포함), 피크 약 0.568, RMS 약 0.0382, 클리핑 표본 0. 연주/음악적 품질의 청취 판정과는 구분.
- 최종 PDF 1쪽을 PNG로 확인. 네 마디씩 배치하고 Ped./* 표기를 위한 세로 공간을 확보한 로컬 출력 설정 사용. 음표나 원본 XML의 시간은 바꾸지 않음.
- 재현용 로컬 QA: `output/letter-on-the-breeze/qa/browser.json`, `browser_check.cjs`, `render_pdf.cjs`, 다운로드 파일 및 화면 PNG.

## 재현과 위험

```powershell
python -m musigen piece examples/pieces/letter_on_the_breeze --out output/breeze_rebuild --corpus-accompaniment
```

기록한 자료 버전에서는 재현되지만 라이브러리가 바뀌면 새 선택은 달라질 수 있다. 확정된 음표 재생에는 보관한 v003의 스냅샷을 사용한다. 실제 선택 결과·음원·PDF는 모두 output에만 있고 저장소에는 올리지 않는다.

음악의 설득력, 연주 감촉, 주제의 인식 가능성은 아직 사용자 청취 검수가 필요하다. 기존 분석·검색 계수와 기본 적용 여부는 바꾸지 않았다. Ped./*는 이번 피아노 곡에서 선택했고 다른 곡의 선 표기는 유지된다. main 작업 폴더 및 공개 사이트는 수정하지 않았다.
