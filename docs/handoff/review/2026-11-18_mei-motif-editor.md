# 작곡 작업실 악보 입력기 검수 요청

2026-11-18 · `codex/mei-motif-editor` · 기준 커밋 `0227374` · [작곡 작업실](http://127.0.0.1:8808/compose.html)

## 사용 흐름

기존에는 건반으로 입력한 음을 별도 미리보기에서 확인했다. 이제 작업실 위쪽 악보에서 음표·쉼표를 직접 선택한다. 건반은 선택의 마지막 음 뒤에 입력한다. ‘건반 입력 음가’는 다음에 넣을 음의 길이를 정하고, 음표 칸 아래 −/+는 해당 음 또는 선택한 음들의 길이를 바꾼다. 세로 드래그로 음높이를 바꾸고 Shift·Ctrl·⌘ 클릭으로 여러 음을 선택할 수 있다. 같은 음높이의 이웃한 음은 붙임줄로 연결하고 인접한 세 음·쉼은 3:2 셋잇단으로 묶는다. 실행 취소와 다시 실행은 현재 작업실 탭에서 동작한다.

조표·박자는 곡 설정을 따른다. 음자리표는 음역의 중앙값으로 정하고 높은음자리표 또는 낮은음자리표를 직접 선택할 수 있다. 자동 생성, 음가 랜덤 생성, 직접 입력, MIDI·MXL·MusicXML 구간 가져오기 모두 같은 편집기를 쓴다.

## 구현과 실행

- `editor/Keyboard.tsx`, `pitch.ts`, `queryEdit.ts`에 MusicSearch의 C2~E6 음높이 배열과 음이름, 선택 뒤 삽입·음가 단계 편집·붙인 음의 이조 방식을 적용했다.
- `editor/Editor.tsx`의 `MotifEditor(value, onChange, …)`가 건반·음표별 편집과 SVG 조작을 연결한다. `mei.ts`의 `toMEI`는 마디 경계에서 음을 분할하고 각 조각을 원래 이벤트 ID에 연결한다. Verovio 인스턴스는 입력기 전용으로 생성하고 화면 해제 시 정리한다. 작업실이 로드한 WASM을 가져오기 창·완성 악보와 공유한다.
- `editor/model.ts`의 `fromClip`, `toClip`은 v1 모티프의 음높이와 실제 길이를 유지한다. 붙인 음은 작곡·재생에서 한 음이며, 기보를 복원할 때는 선택 필드 `editorNotation`을 사용한다. 리듬 변주 뒤에는 새 음가와 일치하는 기보만 복원한다.
- `editor/index.tsx`가 편집 이력과 피아노 재생 이벤트를 관리한다. `musigen/workshop.html`, `workshop.js`, `workshop.css`는 입력 악보와 완성 악보에 별도 표시 영역을 제공한다.
- `musigen/studio.py`의 `write_studio`가 `editor/build.mjs`로 React 편집기를 빌드한다. 로컬에서는 Node 24, `MUSICOMP_ROOT` 아래 설치된 Vite·React 및 Verovio를 사용했다. 편집기 자체 의존성은 `editor/package.json`에 선언했다. 빌드 결과는 출력 폴더의 `assets/motif-editor.js`에 둔다.

## 확인한 결과

- 8808 작업실에서 C4–D4–E4 입력 후 첫 음을 8분음표로 줄이고 두 번째 음을 E4로 드래그했다. 실행 취소와 다시 실행을 확인했다. 연속된 E4 두 개를 붙여 실제 길이 2박을 얻었다. 개별 음가 −/+ 및 ♭ 건반의 Enter 입력도 확인했다.
- 한 박 안의 E♭4–F4–G4를 셋잇단음표로 표시했다. E♭장조·낮은음자리표와 마디선을 지나는 긴 음을 적용했다. B♭3 1/3박·쉼 1/2박·E♭4 5박의 독립 Verovio 재해석에서 실제 음높이 58·63, 총 35/6박을 확인했다.
- 검증용 작업실에서 MIDI 트랙 3의 G4–쉼–A4, MXL의 C3–쉼–D3, XML의 E♭4–쉼–F4를 선택해 복사했다. Ctrl+V로 입력 악보를 갱신하고 클립보드 차단 시 수동 복사를 확인했다.
- 검증용 작업실에서 자동 생성·부분 이어쓰기 후 곡을 저장해 피아노·기타·가야금·2/3/4중주를 열었다. 여섯 편성의 MusicXML과 재생 버튼을 확인했다. 8808에서는 기존 ‘두 박에서 시작한 노래’ 4중주 링크를 열어 입력 모티프와 완성 악보를 확인했다. 데스크톱·390px 화면 폭도 점검했다.
- TypeScript 엄격 검사 및 편집기 회귀 테스트 5개 통과. Python 전체 291개 중 290개 통과. 이전 꾸러미와 동일하게 `test_phrase_observations_have_real_breaths_and_all_notes`에서 외부 프레이즈 분절 결과(4구절)와 기대(6구절)가 다르다.

## 적용 범위

8808 작곡 작업실의 기본 입력기에 적용했다. 단선율 기준이며, 다성 파일은 가져오기 창에서 파트와 성부를 고른다. 입력 악보의 조표·박자는 편집 중인 곡 설정을 사용하므로 원본 악보의 중간 전조·박자 변경은 구간에 복원되지 않는다. 작곡·편곡의 음악적 결과에 대한 새 청취 평가는 이번 UI 검증에 포함하지 않았다.
