# 피아노 건반·음가 변주·XML 구간 입력 검수

2026-11-18 · `codex/workshop-keyboard-xml` · [작곡 작업실](http://127.0.0.1:8808/compose.html)

## 입력과 생성

MusicSearch의 Keyboard.tsx에서 사용하는 C2–E6 범위와 흰건반·검은건반, 임시표 선택 방식을 작업실에 적용했다. workshop_keyboard.js는 선택한 음가로 음과 쉼을 추가한다. 음가 적용 목록 또는 모티프 미리보기에서 기존 음·쉼을 골라 길이를 수정할 수 있다.

자동 모티프 생성 뒤 ‘음가 랜덤 생성’을 누를 때마다 현재 사건열에서 음높이·순서·쉼 자리(사건 순번)를 보존해 새 음가를 뽑는다. 시작 시각은 달라진다. motif_workshop.rerhythm은 기존 노래방 4음 리듬 묶음의 지지 수를 참고해 이웃한 두 사건의 총길이를 재분배한다. 한 음뿐인 경우처럼 재분배할 수 없으면 새 전체 길이를 허용하고 화면에 표시한다. 자동·직접 입력·가져온 모티프에서 동일하게 동작한다.

## 악보 구간

workshop_import.js가 로컬 .xml/.musicxml 파일과 MusicSearch 5178의 카탈로그 검색 결과를 한 창에서 연다. workshop_catalog.py는 카탈로그 검색과 제공된 기보 전용 XML을 읽는다. DB의 미리보기 범위가 적용되면 화면에 표시한다. 로컬 파일은 브라우저에서 읽는다.

파트를 고르면 해당 파트의 악보를 표시한다. 보표·성부와 마디/음표 단위를 고르고 시작·끝을 클릭하거나 목록에서 지정한다. 다쪽 악보는 쪽을 넘기며 선택을 유지한다. 마디 선택은 음이 없는 앞뒤 시간까지 쉼으로 포함한다. 동시 화음은 사용자가 윗음 또는 아랫음을 선택해 단선율로 가져올 수 있다. 선택 범위·성부·화음 처리 방식과 DB 작품 ID를 모티프에 기록한다. 악보 원문과 검색 DB는 저장소에 추가하지 않는다.

## 검수 경로와 결과

- 8808 실제 브라우저에서 53건반, D♭4·F4 입력, 첫 음의 길이 수정, 음가 변주 5회 연속을 확인했다. 각 회차의 음높이 열은 같고 직전 회차와 음가가 달랐다.
- ‘두 박에서 시작한 노래’의 원본 XML에서 첫 음부터 세 번째 사건까지 눌러 E♭4 반 박·반 박 쉼·F4 한 박을 가져왔다.
- DB에서 Mozart로 검색해 실제 피아노 악보를 열고 2~3번째 마디를 화면에서 골라 윗음으로 추출했다. 모바일 390px에서 페이지 전체의 가로 넘침이 없었다.
- 전체 테스트 288개 중 287개 통과. 기존 외부 musicomp 프레이즈 분절(실측 4, 기대 6) 차이 1개가 남는다. 신규 음가 보존·한 음 처리 테스트는 통과했다.
