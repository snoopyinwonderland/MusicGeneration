# 노래방 전체 주선율·화성 통계 검수 요청

브랜치 `codex/karaoke-corpus-statistics`, 기준 `e34aa95`. 사용자는 노래방 전체 데이터의 음형·음정·contour·화성 진행을 조사하고, 필요 요소와 개발 기록을 추가하며, 랩을 제외하고 음형 묶음 단위의 방법을 고안하도록 요청했다.

## 결과와 전후 차이

이전에는 기본 음정 빈도와 일부 차트 곡의 2마디 조합을 사용했다. 이번에는 50,874개 MIDI를 전수 시도하여 50,550개 유효 파일, 324개 사유별 제외, 미처리 0개를 기록했다. 중복 제거 선율 50,459개에서 랩 자리표시 의심 2,622,402음을 제외한 17,301,510음을 분석했다. 4/6/8음 음형·리듬·contour, 앞뒤 음정 전이, 쉼·박 위치, 2/4/8마디 재현, 명시 화음과 선율의 동시 관계를 조사했다.

59계열, 3,481,274개 패턴 집계 행과 1,525,867개 검색용 2/4마디 구간을 저장했다. 패턴마다 출현 수와 지지 선율 수를 구별한다. 곡별 동일 가중치, 곡 내 2마디 반복을 한 번만 세는 결과를 추가했다. 새 곡은 만들지 않았고 생성 기본값은 바꾸지 않았다.

[보고서](http://127.0.0.1:8808/karaoke-statistics.html), [방법·실측·실행 안내](../../KARAOKE_CORPUS_STATISTICS.md), [개발 기록](../../DEVELOPMENT_LOG.md). 로컬 DB와 원본 음표는 `output/karaoke-statistics-20261118`에만 있다. 8808 목록에 데이터 분석 항목을 추가하고 종료돼 있던 같은 로컬 서버를 127.0.0.1 바인딩으로 재시작했다.

## 변경 파일과 함수

- `musigen/karaoke_statistics.py`: `extract`는 S1/channel 4와 원 코드 트랙·메타데이터만 읽는다. `rap_mask`/`split_runs`는 제외 구간을 건너뛰지 않는다. `analyze`는 음형·구간·화음 관계를 수치화하고, `aggregate`는 지문별 중복을 제거해 빈도/지지 수를 SQLite에 저장한다. `run`은 인벤토리·에러·진행/완료를 기록하고 변경된 원본의 캐시 재사용을 거절한다.
- `scripts/karaoke_block_context.py`: 같은 2마디의 곡 내 재출현을 한 번만 세는 비교, 원본 모드/박자/마커·미해석 코드 범위.
- `scripts/validate_karaoke_statistics.py`: 독립 음표 파서·원본 해시·특성 재계산·분모 검증.
- `scripts/report_karaoke_statistics.py`: 완료된 집계만 읽어 한글 HTML/Markdown·요약·조건부 음정 전이 확률표 출력. 확률표는 관찰 빈도이며 평활화·생성 학습 모델이 아니다.
- `tests/test_karaoke_statistics.py`: 랩 제거 후 가짜 연결 방지, 겹침·쉼, 모호한 재발음, 없는 박자/조성, 미해석 코드, 긴 음, 이조 반복, 파일 중복과 패턴 지지 수 검증.
- `AGENTS.md`, `docs/DEVELOPMENT_LOG.md`: 사용자 지시대로 개발 기록을 항상 남기는 규칙과 실행 기록.

## 검증

40파일 시범 실행 후 전수 추출. 독립 파서 대조에서 같은 음 재발음의 길이 모호성을 발견해 v2가 해당 147파일을 제외하도록 보완했다. 저장된 원본 추출을 재검증해 집계를 다시 했고 원본 자체는 변경하지 않았다. 나머지 제외는 짧거나 잘못된 음가 98, 동시 발음 70, 조표 충돌 3, S1 없음 4, S1 중복 2다.

최종 64파일(성공 경로 전체에 일정 간격 배치)은 독립 SMF 읽기의 시작·끝·음높이/PPQ 일치, 원본 해시와 특성 재계산 일치. 원본 50,874개 파일의 크기·수정시각이 실행 전후 일치했다. SQLite quick_check 정상, 패턴 출현/지지 수 분모와 구간 수 확인. 새 테스트 9개 통과. 전체 283개 중 282개 통과, 기존 `test_phrase_observations_have_real_breaths_and_all_notes` 실패 1건(외부 musicomp 분절 4구절 vs 기존 기대 6구절)은 그대로 남았다.

HTTP 200·보고서 제목/모드 비트 한계/전체 수·작품 목록 링크를 확인했다. 로컬 브라우저 접근 도구가 이번 채팅에서 불가하여 시각 검수는 하지 못했다.

## 한계와 다음 단계

- MIDI 장단조 비트가 분석 대상 모두 0이다. `major:*`는 실제 장조·으뜸음 판정이 아니다. 조표 관계장조 기준의 반음 좌표로만 사용하고 기능화성/종지 정답 학습은 보류한다. 근음 이동과 화음 구성음은 이 비트에 의존하지 않는다.
- A4 8음 반복은 랩 의심 휴리스틱이다. 실제 노래의 반복음도 제외할 수 있다. 모호한 파일과 미해석 코드를 자동 수정하거나 추정하지 않는다.
- 쉼 기준 구간과 비중첩 마디 창은 사람의 프레이즈 정답이 아니다. 경계를 가로지르는 음을 가진 창 등이 제외되어 표본 편향이 있다. 빈도는 선호·품질·표절 판단이나 고정 생성 비율이 아니다.
- 주선율과 화성의 전체 지문 중복 기준이 달라 각각의 분모를 유지한다. 장르·인기도별 통제와 작품 단위의 모든 편곡 통합은 아직 없다.
- 다음은 묶음의 역할·앞뒤 문맥을 검수하고, 동일 주제의 변형 관계를 먼저 설계하는 생성 비교다. 음 하나씩 뽑는 모델을 이 통계만으로 품질 개선 완료로 보고하지 않는다.
