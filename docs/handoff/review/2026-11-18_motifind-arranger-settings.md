# MOTIFIND 기본 작곡과 전체 편곡 작업대

브랜치 `codex/motifind-arranger-settings`. [새 곡](http://127.0.0.1:8808/compose.html) · [기존 8마디 곡의 전체 편곡 작업대](http://127.0.0.1:8808/compose.html?piece=360b156a67e8413aaf05b61f0cba1175&workspace=arranger)

## 적용

사용자 요청에 따라 노래방 인접 두 마디 통계를 사용하는 선택지를 ‘MOTIFIND 작곡 시스템’으로 표시하고 새 8·16마디 작곡의 기본값으로 올렸다. HTML의 초기 선택과 `motif_workshop.compose`의 필드 생략 기본값을 맞췄다. 내부 값 `neighbors`, `classic`과 방식 기록이 없는 구버전의 재열기 동작을 보존했다.

‘전체 편곡 설정 · 모든 악기 편성’을 누르면 현재 선율과 화성 MusicXML을 미리 선택한 원본 musicomp 작업대가 열린다. ‘새 창에서 열기’도 제공한다. 첫 편곡의 급수·스타일·화성·앙상블 선율 분담·악기 구성부터 이후 전주·구간 편집·추가 버전까지 원본 화면과 API를 사용한다. 단축 편곡 메뉴에서는 기존 피아노·기타·25현 가야금 등을 고를 수 있다.

`musigen/workshop_arranger.py`가 저장된 곡의 ID를 검증하고 입력 파일을 준비한다. `editor/arranger.mjs`가 musicomp의 Vite 설정을 불러온다. 현재 악보의 초기 선택만 메모리에서 연결한다. 원본 프로젝트에 설치된 Node 의존성이 필요하다. 원본의 새 곡 상태 초기화 코드가 바뀌면 이 연결도 확인해야 한다. 작업실별로 로컬 서버 하나를 사용하며, 입력·편곡 결과·Vite 캐시는 해당 작업실 출력 폴더 옆의 `-arranger` 폴더에 저장한다. 원래 편곡 서버의 작품 목록과 별도로 보관한다.

## 검증

- 브라우저에서 새 페이지의 MOTIFIND 기본 선택과 개발 방식 필드가 없는 예전 곡의 ‘기존 모티프 변형’ 복원을 확인했다. 서버에 발전 방식 필드를 생략한 작곡 회귀 테스트에서도 MOTIFIND가 기록됐다.
- 8마디 샘플의 전체 편곡 작업대에서 기본 7급으로 플루트 이중주와 색소폰 사중주를 선택해 편곡을 생성했다. XML의 실제 파트는 각각 플루트·피아노와 소프라노·알토·테너 색소폰·피아노였다. 원본의 기본 피아노 독주·현악 이중주·삼중주·피아노 사중주도 생성됐다.
- 저장된 링크에서 편곡기 초기 입력과 두 번째 편곡 버튼을 확인했다. 모든 개별 조합을 각각 생성하거나 청취하지는 않았다.
- 8808 배포와 전체 Python 회귀 테스트에는 기존 검증된 동일 모티프 입력기 번들을 사용했다. 이 환경의 pnpm 링크를 통한 기존 입력기 재빌드가 지연됐다. 편곡 작업대는 원본 프로젝트 루트의 Node 의존성을 사용해 실행했다. 292개 중 291개 통과했고 기존 외부 프레이즈 분절 기대값 차이 1건이 남는다.
