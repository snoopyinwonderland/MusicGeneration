## 무엇을 왜 만들었나

사용자가 Count On Me 주선율, 반음계, 편곡 엔진의 lyrical 스타일을 요청했다. 로컬 Melody 악보 4–7마디의 첫 노래 구절을 추출하고 32마디 곡으로 발전시켰다. 원주제 크레딧을 유지하고, 새 선율 발전·화성과 기존 엔진의 반주 실현을 구별했다.

## 바뀐 파일·함수와 실행

추적 파일은 `docs/COUNT_ON_ME_LYRICAL_STUDY.md`, 이 검수 요청서, `README.md`, `docs/PLAN_STATUS_2026-11-11.md`다. 프로덕션 함수·계수·기본값 변경은 없다.

Git 제외 `output/count-on-me/author.py`의 `extract`, `compose`, `arrange`가 추출·설계·실제 엔진 호출을 맡았다. `musicomp.stages.build_stages`에 `style_plan=[{'from_bar':1,'style':'lyrical'}]`을 전달했다. `refine.py`에서 엔진 왼손 리듬 위에 구성음을 보충하고 8·24마디 쉼과 32마디 끝맺음을 작성했다. 원본과 musicomp는 읽기 전용으로 사용했다.

## 위험과 남은 판단

1. 청취 전이다. 원곡 구절 이후의 새 진행이 자연스럽고 주제 관계가 들리는지 판단이 필요하다. 자동 관찰 점수로 이를 대신하지 않는다.
2. 24마디 후반의 G7은 솔로의 의도한 양손 쉼으로 연주하지 않는다. 요약 악보에는 완전 화음을 남겼고 감상 페이지에서도 이 차이를 설명했다.
3. 기존 로마자 표시는 B7–Em6 같은 모든 세컨더리 관계를 기능적으로 표시하지 못한다. 새로운 전조 분석으로 주장하지 않았다.
4. source motif 추출기의 기존 붙임줄 제한을 우회해 무시하지 않았다. 이 곡에서는 붙임줄을 보존하는 기존 XML 리더와 독립 순회로 추출했다. 일반 추출 API 수정은 하지 않았다.
5. 입력 선율과 출력·반주 자료는 Git 제외다. 이 브랜치는 로컬 산출물의 기록이며 저작권 음표를 원격 저장소에 포함하지 않는다.
