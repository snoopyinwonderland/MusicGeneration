# 검수 요청: 현악기 음원 확장과 제공 모티프의 바이올린–피아노 듀엣

- 날짜: 2026-10-23
- 브랜치: `codex/string-instrument-audio`
- 기준: `fad4bad` (최신 favicon 포함)
- 상태: 선택 기능 구현·자동 검사·화면 검증 완료. 사용자 청취 승인 및 main 기본 적용 전.

## 사용자 요청과 범위

사용자는 Super Mario theme의 첫 모티프를 이용한 바이올린–피아노 듀엣과 비올라·첼로 음원 추가를 요청했다. 이후 `musicanote-motif` v1 데이터를 직접 붙여 주며 “이걸로 하죠.”라고 했다. 입력 출처는 `Super Mario Theme Melody.musicxml.xml`, P1/staff 1/voice 1, 1마디 0박부터 2마디 3박까지다. 제공된 7박만 사용했으며 원곡의 다른 구간을 가져오지 않았다.

이번 브랜치는 재생용 악기를 확장하고 선택형 현악기–피아노 듀엣 옵션을 추가한다. 원곡 화성 인식 규칙·musicomp·MusicAnalysis·main은 수정하지 않는다. 악보와 모티프 입력 및 출력은 AGENTS.md대로 로컬 ignored `output/`에만 보관한다.

## 바뀐 파일과 동작

- `musigen/instruments.py`: 바이올린·비올라·첼로의 이름, MusicXML GM 번호(41/42/43), 음자리표, 보수적인 검수 음역.
- `musigen/duet.py`: `parts`, `write_duet`, `save_duet`에 선택 악기와 명시적 선율 옥타브 이동. 기본은 종전 바이올린/0옥타브. 피아노는 이동하지 않고, 범위 초과·다음 비지원 악기는 거부. 버전에 악기·이동량 기록.
- `musigen/__main__.py`: `duet --instrument violin|viola|cello --lead-octaves -2..2`. 샘플은 기존 `--piano-samples`로 켠다.
- `musigen/listen.py`: 실제 MusicXML 파트/보표/GM 번호로 재생 악기를 연결하고 해당 악기 샘플만 포함한다. 옥타브 이동 시 표현의 음높이와 최저음 기반 화성 분석에도 반영한다. 기본 솔로에 새 샘플을 불필요하게 넣지 않는다.
- `musigen/listen_template.html`: 비올라·첼로 음원 로딩, 현악기 공통 재생, 해당 악기만 보이는 음소거, 악기 이름·WAV 출처. 피아노 페달은 피아노에만 적용한다.
- `musigen/assets/{viola,cello}/`: 고정된 FluidR3 버전에서 샘플을 선택, JSON·출처·원본/개별 해시·PCM 검사 기록. 각각 15개/16개, 약 0.51/0.55MB. MP3 바이트는 변경하지 않았다.
- `scripts/render_score_pdf.cjs`: 선택 듀엣의 악기 이름 표시.
- `tests/test_string_instruments.py`, `scripts/test_playback.cjs`: 음역·옥타브·보표·MIDI 악기·피아노 보존·음원 무결성·공유/내장 자산·페달 분리 검사.
- `scripts/check_strings.cjs`: catalog 기반 실제 브라우저 재생·분리 청취용 렌더·음소거·다운로드·화성 전환·반응형 검수.
- `README.md`, `.gitattributes`: 사용법과 JSON 바이트 보존.

재생 계층은 지원 악기가 여러 파트에 놓인 보표 대응을 읽지만, 작곡 명령은 현악기 한 대와 피아노를 대상으로 한다. 바이올린·비올라·첼로의 독립 성부를 자동으로 만드는 실내악 편곡기는 이번 범위가 아니다.

## 새 듀엣: 작은 모험의 대화

제목·C장조·4/4·♩112·24마디/51.43초는 작곡 제안이다. 제공 모티프의 음높이와 쉼을 포함한 음가는 요청 조건이다. 원형 선율의 저작자를 Codex로 표기하지 않았으며 추가 선율·발전·화성·반주의 역할을 구분했다.

| 마디 | 구조 | 확인할 음악 |
|---|---|---|
| 1–4 | 주제와 첫 응답 | 첫 7박 원형 + 새 한 박 쉼, 피아노 응답 |
| 5–8 | 한 걸음 위의 대답 | 모티프 한 음계 단계 이조, 하행 응답, 으뜸화음의 쉼 |
| 9–12 | 상행 발전 | 첫 마디 조각을 E/G/B에서 시작, 11마디 B5 절정 |
| 13–16 | 긴 숨 | 첫 마디 음가 두 배 확대, p와 부드러운 분산반주 |
| 17–20 | 주제의 귀환 | 원형 7박 재현, 변형 조각과 쉼 |
| 21–24 | 주고받기와 종결 | 단편 뒤 피아노 응답, G7–C 함께 종결 |

반주는 기존 waltz(4/4에서는 스트라이드), alberti, broken, shell을 사용했다. 드래프트의 19→20마디 병행 8도 경고는 20마디 베이스를 Fmaj7/A로 바꿔 해소했다. 화성 판단 규칙은 수정하지 않았다. 최종 검사 오류 0·경고 0이며 경과음 참고 3개는 유지한다.

프레이즈 계획은 4마디씩 6개다. 자동 분석은 8개 구간을 검출했고 계획한 끝 지점은 6/6 일치한다. 17–20마디는 17–18/18/19–20으로 더 잘게 검출되므로 6개 프레이즈 전체가 정확히 일치했다고 주장하지 않는다. 주선율의 쉼은 32곳/26박이다.

## 로컬 검수 경로와 URL

루트: `K:\Music Generation-codex\output\motif-adventure\`

- `work/`: 제공 모티프, 설계, 악보 입력. `source/v001/`: 내부 피아노 형식 작곡 원본.
- `adventure_duet/v001/`: 실제 바이올린–피아노 MusicXML/MIDI/PDF 및 버전·검사 기록.
- `listen/adventure_duet/v001.html`: 악기 샘플·엔진·PDF 내장 감상 페이지.
- `downloads/`: 실제 버튼으로 저장한 XML/PDF/WAV, 출처, 브라우저 화면 및 검증 JSON.
- 듀엣: `http://127.0.0.1:8788/listen/adventure_duet/v001.html`
- 음원 비교: `http://127.0.0.1:8788/audio/` (기존 자작곡 ‘빛이 머무는 자리’를 피아노/바이올린/비올라/첼로로 비교; 요청한 새 곡과 별개인 음원 검수 자료)

이 컴퓨터의 loopback 서버가 실행되는 동안 이용 가능하다. 재시작:

```powershell
& 'K:\Music Analysis\.venv\Scripts\python.exe' -m http.server 8788 --bind 127.0.0.1 --directory 'K:\Music Generation-codex\output\motif-adventure'
```

음원 비교 생성 버전: `output/string-audio-qa/{piano,violin,viola,cello}/v001`; 브라우저 결과 `output/string-audio-qa/browser/`. 이 자료와 모티프 기반 악보는 공개 Pages에 게시하거나 Git에 넣지 않았다.

## 검증 결과

- Python unittest **77개 통과**, Node 재생 검사 **6개 통과**.
- 두 신규 음원의 **31/31 샘플**을 Chromium Web Audio에서 PCM으로 해독: 무음 없음. 지원 음역 안의 샘플 이동은 최대 1반음. 개별 해시 확인.
- 기존 솔로/바이올린, 신규 비올라/첼로 총 4편성 실제 브라우저 검사. 현악기 각각 68음, 피아노 133음. 각 현악기만 따로 렌더해 RMS 양수 확인(비올라 0.00931, 첼로 0.01231); 피아노 믹스가 무음을 가리지 않도록 검사했다.
- 4편성 XML·WAV 다운로드, 현악기 음소거, 코드 심벌/로마자 전환 중 재생 유지, 보표 아래 화성, 390px/1440px 가로 넘침 없음. Verovio/pageerror 0.
- 새 듀엣은 바이올린 88음+피아노 179음. WAV peak **0.41843**, RMS **0.04825**, 51.929초(잔향 포함): 디지털 클리핑·무음 없음.
- 새 듀엣 MusicXML의 첫머리 및 17마디 재현부: 각각 **10/10 사건(음 7·쉼 3), 7박** 입력 일치. 뒤에 붙인 한 박 쉼을 구분해 확인했다.
- PDF 2페이지 전체를 PNG로 렌더해 확인. 총보·악기 이름·음·쉼·페달·강약이 잘림 없이 표시된다.
- 이번 결과는 자동·시각 검증이며 음악성·음색 균형·운지·활 배분에 대한 사람의 청취/연주 승인과 구별한다.

## 위험과 후속 검수

- 현악기 샘플은 단일 벨로시티 층/약식 지속 루프다. 실제 스피카토·레가토의 활 교체나 연주자 루바토는 재현하지 않는다.
- 새 듀엣의 9–12마디 고음 반복이 날카로운지, 13–16마디 대비가 충분한지, 피아노 응답이 잘 들리는지 청취할 것.
- 새 옵션은 0옥타브가 기본이다. 첼로 등에서 선율이 높다면 사용자가 명시적으로 옥타브 이동을 선택하며, 악기만 바꾼다고 자동으로 재작곡하지 않는다.
- 악기별 운지와 현 교차를 판단하지 않는다. 자동 손 검사는 내부 피아노 원본 기준임을 계속 표시한다.
- 원본 PDF/XML 화성 위치와 화면의 화성 표기/위치 설정은 종전처럼 별개다.
- 공개 Pages는 병합·재생성 후에 기능이 반영된다. 이번에는 codex 브랜치와 로컬 감상판만 제공한다.
