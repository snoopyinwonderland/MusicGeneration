# 2·4·8마디 구절과 화성 시각 참조

기존 프레이즈 참조 자료의 화성·기능 주석에 정확한 시각을 붙여, 한 프레이즈 안에서 화성이 언제 바뀌고 끝을 어떻게 준비하는지 살펴보는 선택 기능입니다. [참조 화면](http://127.0.0.1:8801/library.html)에서 길이·박자·작곡가·프레이즈 끝 포함 여부로 조회하고 참고 JSON을 받을 수 있습니다.

현재는 자료 관찰과 작곡자가 작성하는 발전 설계를 위한 도구입니다. 새 곡 생성·종지 종류 판정·작곡가 스타일 모델은 연결하지 않았습니다. 기존 `piece`, `blueprint`의 기본 출력도 바뀌지 않습니다.

## 범위와 결과

로컬 TAVERN의 지정 작품 B070, M025, M179, M265, M573에서 주제(00)와 첫 변주(01)의 사람 지정 프레이즈만 읽었습니다. 원 파일은 읽기 전용입니다.

| 관찰 | 결과 |
|---|---:|
| 시도한 악보 프레이즈 | 40 |
| 제한된 파서로 시각을 읽은 악보 | 26 |
| 악보와 분석 주석을 하나 이상 정확히 연결한 프레이즈 | 11 |
| 시도한 분석 파일 / 연결한 분석 파일 | 80 / 20 |
| 2마디 / 4마디 / 8마디 구간 | 47 / 25 / 5 |
| 두 분석자의 원 라벨 차이가 있는 프레이즈 | 6 |

총 77개 구간에는 같은 프레이즈의 겹치는 창이 포함됩니다. 77개의 독립 곡이나 검증된 새 프레이즈가 아닙니다. 이번 지정 표본의 처리 범위이며 코퍼스 전체 정확도 추정치가 아닙니다. 이전 자료의 36/40 단선율 관찰이나 56/80 원 주석 읽기와도 기준이 다릅니다. 이번에는 음표·마디·박자 일치까지 요구합니다.

## 시각과 연결의 계약

- 시각은 4분음표 길이 기준 유리수 문자열입니다. `1/2`는 8분음표 길이이며, 6/8의 지휘박 한 개를 뜻하지 않습니다.
- 같은 사람 지정 프레이즈 파일 안의 **연속된 온마디**만 2·4·8개씩 묶습니다. 여린내기·마지막 부분 마디를 채우거나, 서로 다른 프레이즈 파일을 이어 붙이지 않습니다. 내부 창을 새 프레이즈 경계로 인증하지 않습니다.
- 악보와 Joined 분석의 박자 문자열, 전체 길이, 마디 시작·길이, 각 `**kern` 성부의 모든 원 음표 토큰·시각이 같아야 연결합니다. 조표나 이명동음 표기를 자동 수정하지 않습니다. 인쇄 마디 번호는 달라도 시각이 같으면 연결하되 양쪽 원 표기를 따로 보존합니다.
- 분석자 A와 B는 별도 트랙입니다. 둘 다 연결된 경우 시간축의 합집합에서 원 라벨 차이를 표시합니다. 일치가 정답 인증을 뜻하지 않으며, 한 명만 연결된 경우 두 사람의 합의로 표시하지 않습니다.
- `**harm`와 `**function`은 다른 층입니다. T/P/D는 원 분석자의 프레이즈 모형 주석이며, 매 화음의 기능 정답으로 재해석하지 않습니다. 마지막 I/V만으로 PAC/IAC/HC 같은 종지 종류를 만들지 않습니다.
- 창 경계에서 화성 주석을 자르면 `source_onset`, `source_duration`, 원 토큰, 원 행 번호와 `clipped_at_window`를 함께 보존합니다. 창 안 좌표와 원 파일 좌표를 구별합니다.
- 원 조성 토큰은 성부·시각과 함께 보존합니다. 국소 조성/전조를 정규화하거나 추론하지 않습니다. 반복은 펼치지 않습니다.
- 선율 관찰은 기존 `upper_staff`가 단선율 후보를 읽을 수 있을 때만 제공합니다. 다성부 최고음을 임의 주선율로 쓰지 않습니다. 창 이전에 시작한 지속음은 새 발음으로 세지 않고, 창 안에서 시작한 음의 원 음가는 끝을 넘어가도 보존합니다.

파서는 고정 성부의 `**kern`·`**harm`·`**function`, 명시적 reciprocal 음가·점음표와 0길이 장식음을 지원합니다. 성부 분기·결합, 박자 변경, `%` 음가, 생략된 음가 등은 미지원으로 남깁니다. 원 자료 오류와 파서 미지원은 서로 다른 사유입니다. 기준은 [Humdrum **kern 규격](https://www.humdrum.org/rep/kern.html)이며 범용 Humdrum 파서를 대체하지 않습니다.

## 확인할 사례

| 구간 | 관찰할 내용 |
|---|---|
| `B070_00_01:2:1` | 6/8의 여린내기 다음 온마디 둘. 원 구절 1/2–13/2박이며 첫 2마디의 화성은 I(3/2박), V7(3/2박), I(3박)로 연결됨 |
| `M265_01_01:8:0` | 2/4 전체 8마디. A는 처음 네 마디에서 마디 단위로 화성이 바뀌고, 뒤에는 더 짧은 시각 단위가 나타남. B는 15/2박에서 viio/ii를 따로 주석함. 원 라벨 차이 3구간 보존 |
| `M179_01_03:8:0`, `:8:1` | 9마디 프레이즈의 서로 겹치는 두 8마디 창. 첫 창은 원 프레이즈 끝을 포함하지 않고 두 번째는 포함함. 동일한 종결 구간으로 합치지 않음 |
| `M265_00_01:8:0` | B만 연결됨. A 파일 내부의 4/4·2/4 충돌을 고쳐 합의 자료로 만들지 않음 |

M025는 원 악보 4/4와 Joined의 2/2가 달라 제외했습니다. 둘의 온마디 길이가 같다는 이유로 동일 박자로 처리하지 않았습니다. 인쇄 마디 번호 생략과 실제 시각 불일치도 구별했습니다.

## 실행과 내보내기

작업 트리 루트에서 실행합니다. 새 JSON 파일만 만들며 기존 JSON을 덮어쓰지 않습니다. HTML은 같은 이름의 형제 파일로 생성합니다.

```powershell
$env:MUSICOMP_ROOT = 'K:\Music Composition'
$env:PYTHONUTF8 = '1'
$env:PYTHONDONTWRITEBYTECODE = '1'
& 'K:\Music Analysis\.venv\Scripts\python.exe' -m musigen.phrase_context --root 'K:\MusicSearch\data\classical-corpora\tavern' --works B070 M025 M179 M265 M573 --out output/context-v002/library.json
& 'K:\Music Analysis\.venv\Scripts\python.exe' tools/verify_phrase_context.py --root 'K:\MusicSearch\data\classical-corpora\tavern' --library output/context-v002/library.json --out output/context-v002/verification.json
& 'K:\Music Analysis\.venv\Scripts\python.exe' -m musigen.phrase_context --library output/context-v002/library.json --unit M265_01_01:8:0 --out output/context-v002/eight-bar-reference.json
& 'K:\Music Analysis\.venv\Scripts\python.exe' -m http.server 8801 --bind 127.0.0.1 --directory output/context-v002
```

내보내기는 `musicanote-phrase-context` v1입니다. 구간·분석자별 시각과 원 라벨·출처 경로/SHA-256·라이선스 SHA를 포함합니다. `author_decision`과 `user_selection`은 null이며 `generation_eligible`은 false입니다. 화면에서 자료를 조회하거나 받는 행동을 사용자의 곡 선택·승인·학습 예제로 기록하지 않습니다.

원 자료는 [TAVERN](https://github.com/jcdevaney/TAVERN), Devaney 외, CC BY-SA 4.0입니다. 산출물과 원 악보·음표 행은 `output/`에만 두며 Git에 넣지 않습니다. 자체 완결 HTML에도 참고 주석과 출처가 포함되므로 공개 배포 자료와 구별해야 합니다.

## 검증과 다음 적용

전체 테스트 170개, 별도 music21 파서로 연결 가능한 11개 프레이즈의 모든 성부 음표·쉼표 시각 및 마디 길이를 교차 확인했습니다. 원 파일 120개의 SHA-256 일치, 77개 창의 화성·기능 주석이 겹침·빈틈 없이 전체 시간을 덮는 것도 확인했습니다. 이는 시간축·출처 검증이며 화성 해석이나 청취 품질 검증은 아닙니다.

작곡에 쓸 때는 참조의 음들을 복사하기보다, 유지할 리듬·화성 변화 시각·종결 준비를 새 모티프에 맞춰 `development_recipe`의 작성 결정으로 적습니다. 국소 조성과 전조의 명시적 주석 검증이 다음 자료 단계입니다. 기존 P3 통계와 P4 모델의 중단 판정, 보류된 모차르트 스타일 자동 생성은 그대로입니다.
