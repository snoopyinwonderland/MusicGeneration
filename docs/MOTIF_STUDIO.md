# 모티프 입력과 작곡가 참조

```powershell
$env:MUSICOMP_ROOT='K:\Music Composition'
python -m musigen studio --out output\studio --port 8794
```

브라우저에서 `http://127.0.0.1:8794/`를 엽니다. 서버는 loopback에서만 수신합니다. 정적 HTML로도 입력·미리듣기·요청 파일 받기가 가능하지만 **작곡 요청 저장**에는 위 서버가 필요합니다. 파일을 외부 서비스로 전송하지 않습니다.

## 화면과 저장

1. 모티프 JSON 붙여넣기·파일 열기 또는 MusicXML 파트/보표/성부와 시작·끝 선택.
2. 입력 악보와 피아노 샘플 미리듣기로 음·음가·쉼 확인. 단선율만 받습니다. 편집한 텍스트는 다시 읽기 전 저장할 수 없습니다.
3. 분위기, 시작 조성, 박자, 길이, 세컨더리 화음·증6화음·전조 허용, 출력 버전 선택.
4. 선택적으로 모차르트·베토벤·쇼팽 참조 지정.
5. 작곡 요청 저장 후 대화에서 “방금 저장한 모티프로 진행해 주세요”라고 전달.

저장 위치는 `output/studio/requests/request-<uuid>/`입니다. `request.json`은 모티프와 요청 조건, `motif.json`은 원 모티프, `status.json`은 `awaiting_composer` 상태를 담습니다. 파일 이름을 입력에서 받지 않으며 매 요청은 새 폴더에 저장합니다. 서버 재시작은 요청 파일을 지우지 않습니다. 저장 후 변경한 화면 내용은 다시 저장해야 합니다.

요청의 `preferences.tempo`는 박자와 무관하게 4분음표/분입니다. 6/8 설계의 `design.basics.tempo`는 점4분음표 기준이므로 요청을 발전 설계로 옮길 때 1.5로 나누어야 합니다.

현재는 **요청 저장과 참고 자료 검색까지 자동**, 구절 계획·음표 작성은 대화 속 작곡자가 담당합니다. 저장 버튼이 완성곡이나 학습 모델을 실행하지 않습니다. `blueprint`의 발전 설계는 이 요청과 참고 자료를 읽어 작성합니다.

API는 동일 로컬 Origin의 JSON POST만 받고, 크기를 1MB로 제한합니다. `GET /`는 입력 화면, `POST /api/requests`는 새 요청 저장입니다. 공개 서비스용 인증·사용자 분리 서버는 아닙니다.

## 기존 자료를 다시 자르기보다 연결을 보강

2026-11-10 실제 로컬 `musicomp/knowledge/data/classical/bars.jsonl.gz`를 다시 읽은 결과:

| 참조 | 적격 train 마디 | 작품 묶음 | 프레이즈 위치 있는 마디 | 종지 주석 있는 마디 | 바로 다음 적격 마디 연결 |
|---|---:|---:|---:|---:|---:|
| Mozart sonatas | 2,572 | 14 | 2,531 | 341 | 1,563 |
| Beethoven sonatas | 3,822 | 17 | 3,725 | 463 | 2,629 |
| Chopin mazurkas | 992 | 16 | 985 | 76 | 519 |

작품 묶음은 소나타/opus 등의 기존 분할 단위이며 곡·악장 수와 같지 않습니다. 원 XML 폴더 Mozart 61, Beethoven 114, Chopin 33개에 대한 [내용·중복 검사 결과](RAW_CLASSICAL_SCORES.md)는 별도입니다. 정상 파싱은 207개, 서로 다른 정상 파일 바이트는 188개입니다. Chopin XML에는 에튀드도 있지만 **현재 검색에 연결한 직접 마디 라이브러리는 마주르카**입니다.

`composer_reference.py`는 이 기존 자료에서 선택한 작곡가·코퍼스의 `split=train`, 적격, 확인된 라이선스 행만 사용합니다. 다른 작곡가나 evaluation 행은 검색 풀에 들어오지 않습니다. 작곡가를 지정하지 않으면 이 라이브러리를 읽지 않습니다.

작곡가를 선택해 저장하면 요청 폴더의 `style-reference/`에 다음을 만듭니다.

- `bar-index.jsonl`: 마디별 상대 음정·음가·쉼, 음 밀도, 왼손 밀도와 음형 후보, 화성 주석, 프레이즈 위치, 종지, 출처·원본 해시, 앞뒤 적격 마디 ID.
- `references.json`: 입력 **첫 마디**와 박자·길이가 같은 마디 중 참고 사례 최대 5개. 작품 묶음마다 최대 1개를 제시합니다.

검색 거리는 음 밀도·쉼 비율·2반음 이내 진행 비율 차이의 합인 **잠정 기준**입니다. 작곡가 고유성이나 음악적 품질을 학습한 점수가 아닙니다. 4/4 입력을 시험했을 때 Mozart는 온마디 434개, Beethoven은 727개가 대상이었습니다. Chopin은 3/4뿐이며 온마디 983개입니다. 박자가 맞지 않으면 다른 박자로 바꾸거나 다른 작곡가를 섞지 않고 빈 결과를 남깁니다.

마디 라이브러리는 다성부·붙임줄 등을 보수적으로 제외한 불연속 부분집합입니다. 없는 마디 사이를 이어 완전한 프레이즈인 것처럼 표시하지 않습니다. 선율은 상보표 최고음 후보이고 사람이 확정한 선율 주석이 아닙니다. 코드의 앞뒤 연결은 기보 순서이며 반복 재생/1·2번 ending의 연주 경로를 확정하지 않습니다.

## “모차르트 스타일로 발전”의 다음 구현

마디 검색만으로 작곡가 스타일을 완성했다고 보지 않습니다. 다음 순서로 확장합니다.

1. **2·4·8마디의 검수된 연결**: 구절의 시작·반복·이어짐·종지를 정본의 연속 음별 기록과 주석에 맞춰 복원. 다성부 및 성부 교차 표본은 사람이 확인하고 불확실성을 표시.
2. **입력 주제에 맞춘 변형 설계**: 원 주제의 특징을 고정하고, 검색한 사례의 반복 간격·조각내기·리듬 확대/축소·응답 위치를 적용. 원곡 선율의 마디 이어붙이기로 대체하지 않음.
3. **화성 경로와 성부 연결**: 국소 조성, 부속화음, 증6화음, 종지 목표와 베이스선을 구절 계획에 연결. 현재의 두 경향음 검사를 전체 내성·해결음 검토로 확장.
4. **비교 청취**: 같은 모티프·길이·난이도로 일반 설계와 작곡가 참조 설계를 비교. 주제 인식, 구절의 설득력, 스타일 특징, 연주 가능성을 따로 평가. 평가용 작품은 참조 검색과 분리.

모차르트의 모든 작품이나 베토벤의 모든 시기를 하나의 통계로 평균내기보다, 초기에는 현재 자료에 맞는 **모차르트 피아노 소나타 참조**로 범위를 명시합니다. 쇼팽 녹턴·에튀드 요청은 별도 자료 검수 전 마주르카 자료로 대체하지 않습니다.
