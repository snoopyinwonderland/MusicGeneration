# 구간별 반주 계획과 실제 음표 검증

상태: 선택 기능 구현·기술 검증 완료, 청취 검수 전, 기본 꺼짐. 기존 musicomp의 프레이즈/구간 경계, 밀도 모델, Viterbi 연결 선택을 그대로 사용합니다. 이번 변경은 작성한 반주 요구를 후보의 실제 음표에 대조하고 전후를 확인하는 기능입니다. 새 검색 계수나 작곡가 스타일 모델을 학습하지 않았습니다.

후속 [3/4·4/4 작성 입력 고정 시험](ACCOMPANIMENT_TRANSFER_TRIAL.md)에서 구성음 생략은 줄었지만 작성 패턴으로 돌아간 구간의 미충족과 성부 연결 경고 증가를 확인했습니다. 아래 6/8 사례의 0개 결과를 일반화하지 않습니다.

## 작성 방법

기존 design 또는 발전 recipe의 `design` 안에 선택 필드 `accompaniment_plan`을 넣습니다. `role`과 `decision`은 작성자의 의도이며 자동 분석 결과가 아닙니다.

```json
"accompaniment_plan": [
  {
    "bars": [1, 4],
    "role": "주제 제시",
    "decision": "화음 성격을 보존하고 구절 끝에서 함께 쉰다.",
    "required_degrees": [3, 7],
    "entry_bass_range": [38, 55]
  }
]
```

- `bars`: 전체 곡의 절대 마디 범위. 서로 겹치지 않아야 하며 일부 구간만 지정해도 됩니다.
- `required_degrees`: 생략 가능, 기본 `[]`. 현재 3과 7만 지원합니다. 지정한 화음에 실제로 있는 철자상의 3음·7음만 요구합니다. sus의 4음을 3음으로, 첨가6음을 7음으로 세지 않습니다.
- `entry_bass_range`: 생략 가능. 각 마디 첫 왼손 발음의 최저 MIDI 음 범위입니다. 허용 범위는 기존 왼손 제한인 28–69 안입니다. 모든 발음의 베이스를 추적하는 조건은 아닙니다. 앞 마디에서 이어진 음은 새 발음으로 세지 않으며 새 발음이 없으면 해당 요구를 충족하지 못한 것으로 보고합니다.
- 쉼·음형·직접 쓴 화음은 기존 악보 블록에서 작성합니다. 위 자유 서술을 프로그램이 음표로 번역하지는 않습니다.

`--corpus-accompaniment`로 자료 반주를 선택하면 기존 유형 필터 다음에 원자료 역할을 확인합니다. 계획이 있는 마디의 후보는 기존 음높이 실현·베이스 정리·난이도 검사를 먼저 실행한 후, 각 화성 구간의 구성음과 시작 음역을 검사합니다. 통과 후보에 기존 연결 비용을 적용하며 검색 가중치는 바꾸지 않습니다. 마디 전체의 다른 화음에서 울린 음으로 요구를 대신 충족시키지 않습니다.

계획을 켠 경로에서는 보호할 직접 반주를 자료 후보 연결에 넣지 않습니다. 검색이 불가능한 마디는 연결을 끊고 작성한 반주를 유지합니다. 최종 실현 뒤에도 조건을 다시 확인합니다. **작성한 대체 반주가 요구를 만족한다는 보장은 없습니다.** 충족하지 못하면 `unmet_plan_bars`에 그대로 드러냅니다. 이 필드가 없는 기존 실행은 기존 동작을 유지합니다.

## 관찰과 비교

`accompaniment_context.json` 및 자료 보고서의 `phrase_context`에 다음을 기록합니다.

- 마디 첫/끝 발음의 최저·최고음, 발음 수, 선율이 쉬는 동안의 왼손 발음, 마지막 쉼 길이.
- 각 화성 구간에서 한 번도 울리지 않은 왼손 3음·7음, 명시 요구의 충족 여부.
- 인접 마디 첫 최저음의 차이, 직전 마지막 발음에서 다음 첫 발음까지 극단음의 차이, 프레이즈 경계 여부.

시각과 쉼은 4분음표 단위의 분수입니다. 펼침화음의 극단음을 실제 베이스·내성 성부로 추정하지 않으며 음악적 품질 점수도 만들지 않습니다. 구성음 생략은 왼손의 해당 화음 구간을 대상으로 하며, 동시 화음이나 오른손까지 포함한 전체 악보의 결핍 판정이 아닙니다.

이미 생성한 두 결과를 `baseline/`, `planned/`에 준비한 뒤 새 비교 페이지를 만듭니다.

```powershell
python -m musigen.accompaniment_review --before output/comparison/baseline --after output/comparison/planned --out output/comparison
```

이 명령은 고정된 악보를 재구성하여 실제 MusicXML과 대조하고, 주선율·화성·국소 조성·박자·빠르기·표현이 다르면 반주만의 비교로 내보내지 않습니다. PDF와 피아노 감상 페이지는 기존 생성 경로에서 먼저 준비하세요.

## 2026-11-11 시험

사용자 승인 “네”에 따라 기존 「햇살의 산책 · 조성 연결 연구」를 기준으로 비교했습니다. 기존 모티프·17개 화성 구간·G장조→E단조→G장조·6/8·16마디·약 29초를 보존하고 페달은 두 버전 모두 없습니다. [비교 페이지](http://127.0.0.1:8803/index.html)의 A는 기존 출력, B는 새 반주 계획입니다.

| 확인 항목 | 결과 |
|---|---|
| 1–3마디 | 첫 최저음 G1–A1–B1에서 G2–A2–B2로 이동 |
| 9–10마디 | 긴 주제 아래 6회씩 발음하던 반주를 화음 1회와 점4분쉼표로 변경 |
| 실제 왼손 변경 | 1·2·3·5·7·9·10·13·14·15마디 |
| 자료 적용 | 1·2·3·5·13마디, 총 5마디 |
| 자료 후보가 없어 작성 패턴 유지 | 7·14·15마디, 총 3마디 |
| 직접 작성 보호 | 4·6·8·9·10·11·12·16마디, 총 8마디 |
| 왼손 3음·7음 생략 화성 구간 | A 8/17 → B 0/17 |
| 두 악보 자동 검사 | A/B 각각 멜로디+화성·피아노 솔로 오류 0, 경고 0 |

1–2마디는 같은 원자료의 연속 마디를 선택했습니다. 316개의 서로 다른 후보 실현 중 95개가 사전 조건을 통과했습니다. 분모는 유형과 역할 필터를 먼저 통과하여 실제로 실현해 본 후보이며 전체 라이브러리나 일반 성공률이 아닙니다. 직접 쓴 9–10마디와 원래 작성 패턴의 복귀도 포함하므로 전후 개선을 전부 자료 검색의 효과로 돌릴 수 없습니다.

모티프 JSON과 멜로디+화성 MusicXML은 바이트가 같습니다. 상세 화성 사건도 같고 `harmony.json`의 계획 해시·자료 검증 출처만 새 버전에 맞게 달라졌습니다. 새 국소 조성 라이브러리는 독립 검증을 통과한 6개 악장의 버전입니다. 이 자료 검증은 청취 타당성이나 스타일 재현을 증명하지 않습니다.

출력: `K:/MusicGeneration/accompaniment-context/output/comparison-v003`. 서버 재시작:

```powershell
python -m http.server 8803 --bind 127.0.0.1 --directory output/comparison-v003
```

기술 검증 204개 테스트 통과. PDF 1페이지를 렌더링하여 배치를 확인했고 피아노 샘플 재생/정지, 로마자 전환, 다운로드 링크를 확인했습니다. 모바일 검수와 사용자 청취 평가는 아직 없습니다. P3/P4 중단과 자동 스타일 생성 보류는 유지합니다.
