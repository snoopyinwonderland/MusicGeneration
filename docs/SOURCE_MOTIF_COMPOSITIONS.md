# 기존 작품의 모티프로 서로 다른 곡 만들기

기존 MusicXML에서 명시한 단선율 구간을 가져와, 같은 모티프를 두 발전 설계에 넣는 작성 흐름입니다. 곡을 고르고 음·화성·전개를 쓰는 것은 현재 대화의 작곡자이며 자동 작품 검색·스타일 학습 모델은 아닙니다.

## 구간 가져오기

```powershell
$env:MUSICOMP_ROOT = 'K:\Music Composition'
python -m musigen.source_motif --source 'my-score.musicxml' --part P1 --staff 1 --voice 1 --start-measure 0 --start-offset 0 --end-measure 2 --end-offset 3/4 --out output/source
```

`--start-measure`와 `--end-measure`는 XML에 인쇄된 measure number입니다. offset은 그 마디 시작부터 4분음표 단위 분수이고, 끝은 포함하지 않습니다. 마디 번호가 없거나 중복되면 거부합니다. 새 출력 폴더만 사용합니다.

결과 `motif.json`은 기존 MUSICANOTE 교환 형식, `source.json`은 원본 경로·해시·원 메타데이터·선택 좌표·전체 길이를 기록합니다. 원본 파일은 바꾸지 않습니다. 판본의 rights 문자열은 원문 관찰이며 배포 허가로 해석하지 않습니다.

성부를 자동으로 추정하지 않습니다. 선택한 part/staff/voice의 겹친 음·화음·붙임줄·미분음은 거부합니다. 장식음을 제외하거나 경계에서 음가를 자르면 warnings에 기록합니다. 시간 공백과 선행 쉼은 보존합니다. 붙임줄이 필요한 경우 기존 브라우저 모티프 작업실을 사용하세요. 반복은 펼치지 않고 기보 음높이를 씁니다.

**모티프 음가와 마디 배치는 별개입니다.** 교환 형식은 음·쉼·음가를 보존하지만 원곡의 여린내기 위치와 마디선을 새 곡에 강제하지 않습니다. 현재 상세 화성 교환 경로는 온마디 시작을 요구합니다. 원 여린내기 그대로의 작곡으로 보고하면 안 됩니다.

가져온 동일한 `motif.json`을 [발전 과정 작성](DEVELOPMENT_RECIPE.md)의 두 입력 폴더에 복사하고 각각의 recipe를 씁니다. 입력 모티프를 사용자 선택으로 꾸미지 않고, 작곡자가 선택한 작품·구간과 이유를 기록하세요. 첫 제시와 두 출력 형식의 선율·상세 화성은 기존 검증이 확인합니다.
